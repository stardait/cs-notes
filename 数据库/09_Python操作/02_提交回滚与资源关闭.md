# 第 09 章 · 提交、回滚与资源关闭

> 程序显示写入成功以前，先问是否已经提交。程序报错以后，再确认前面的写入有没有撤回。

## 学习目标

- 用 commit 和 rollback 管理一笔 Python 写入。
- 故意让批量写的第二条失败，验证第一条也没有留下。
- 区分关闭资源、捕获异常和最终提交。

## 准备

本章用[同一个示例](notes_lab.py)。在 PowerShell 打开本章目录。若你已经做过本节，用另一个空文件名试验；`--db` 要放在子命令前面。
```powershell
python .\notes_lab.py --db c9_batch_lab.sqlite3 init
python .\notes_lab.py --db c9_batch_lab.sqlite3 list
```

## 一、先跑一次成功写入

```powershell
python .\notes_lab.py --db c9_batch_lab.sqlite3 add "窗口函数笔记" 45
python .\notes_lab.py --db c9_batch_lab.sqlite3 list --min 40
```

第一个命令显示提交 1 条，第二个命令是新进程、新连接，仍能读到「窗口函数笔记，45 分钟」。这一步证明了结果落在数据库文件里。示例使用 `autocommit=False`。写成功之后才 `commit()`，读完会结束事务并关闭连接。

## 二、故意让批次的后半步失败

标题唯一。两条里第一条标题新，第二条与第一篇的样本标题「多表查询」重复。在下方命令中，`add-pair` 应返回失败，随后 `list` 的结果也没有「失败批次第一条」。

```powershell
python .\notes_lab.py --db c9_batch_lab.sqlite3 add-pair "失败批次第一条" 15 "多表查询" 25
python .\notes_lab.py --db c9_batch_lab.sqlite3 list
```

打开 `insert_notes` 和 `main` 对照。`executemany` 可以用一份 SQL 处理多组值。具体驱动可能逐次发出，也可能优化为批量语句，应用把这组动作放在同一业务事务内。发生数据库错误时，分支调用 `rollback()`，表示整批放弃。只有返回成功才走 `commit()`。

```text
开始写入
  ├─ 全部成功 → commit → 打印已提交
  └─ 有一条失败 → rollback → 返回失败
```

## 三、数据库事务和 Python 资源各有生命周期

`with closing(conn)` 退出时关闭连接，里面的 `closing(cursor)` 负责收掉游标。提交与回滚由另外的逻辑决定。也可用 `try … finally` 关闭，避免异常绕过清理。MySQL 的客户端连接到服务端，忘关会占用会话；未结束的写入还可能持锁。

不知道提交是否成功时，不应该直接重放一次可能扣费或重复插行的操作。真实应用用业务请求编号等明确标识判断是否已经处理。练习用唯一标题看入库冲突，不把标题当作通用的业务请求编号。

## 小结

写入成功需要正确的目标、完整事务和明确提交。验证回滚用一次独立查询，让状态说话。

### 练习 2 · 关闭连接能代替提交吗

如果去掉示例中的 `commit()`，只保留关闭连接会怎样？

<details>
<summary>展开参考答案</summary>

这份示例关闭自动提交，未提交的改动不会因此自动成为持久结果。成功路径要明确提交，失败明确回滚。
