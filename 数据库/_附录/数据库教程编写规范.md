# 数据库教程编写规范

给维护、补课和扩写这套教程的人。写作时以当前仓库、当前学习者要求和实测数据库为准。仓库中的第 03、04 章是可参考的成品。旧任务说明里和本规范不一致的行数指标、复制方式和答案位置，以当前教程的约定为准。

## 读者与边界

读者学过 Python 基础，已学完 00–02 章，正在练习 MySQL。主要工具是 Windows、HeidiSQL 和 VS Code 的 Markdown Preview Enhanced。SQLite 用来做后续对照。每个 SQLite 段落要写明依赖的版本或设置，用对应引擎验证。

| 完成的章 | 已练的内容 | 后续可直接调用 |
|---|---|---|
| 00 学前准备 | 客户端、服务器、库、表、行、列、主键、首次初始化的含义 | 能找到 `learn` 和表，知道什么语句会改数据 |
| 01 查询基础 | `SELECT`、列别名、计算列、去重、`WHERE`、空值、排序、分页 | 能独立查单表并预测返回主键与顺序 |
| 02 聚合分组 | `COUNT/SUM/AVG/MIN/MAX`、多列及表达式分组、`HAVING` | 能区分统计一行的含义及行条件、组条件 |
| 03 建表与约束 | 创建、检查和修改表；数据类型；主键、自增、唯一、默认值、检查、外键及表关系 | 能判断两张表怎么关联，能解释约束与数据含义 |
| 04 增删改 | 单表增、改、删、批处理、软删、备份回放和安全事务演练 | 能预览写入范围、复查并回滚。事务原理与并发控制留给第 08 章 |

## 排课先写依赖

1. 05 多表查询。复习第 03 章的主键和外键，再讲连接、子查询、结果合并。`INSERT … SELECT` 已从第 04 章延期。等读者会独立写并验证来源查询后，可放到第 05 章末尾选学，或放在后续迁移实战里讲。
2. 06 表设计。以第 05 章实际查过的数据为起点，理解更新、插入与删除异常，再练设计和取舍。
3. 07 索引与性能。用重复可测的数据量和执行计划验证结论。小表样本用于明白逻辑，性能样本另行准备。
4. 08 事务。用两个命名连接演示，写清每一步在哪个连接，说明提交、隔离、锁、冲突和重试。
5. 09 Python 操作数据库。由同一条熟悉的 SQL 迁移到 PyMySQL 和 `sqlite3`，练参数绑定、事务、错误处理及最小可跑脚本。
6. 10 进阶特性、11 实战项目。每个主题先写需要的前置知识和实际交付。进阶业务题先定口径再选语法。

## 每篇怎么写

1. **从一件能办成的事开始。** 目标写成「能预测哪些编号入选」「能解释为什么 6 号保留」等可观察的技能。一课先把一个问题讲透，再处理相似分支。
2. **让读者从数据推导结果。** 开头说清数据库、表、起始行数、要核对的样本。例子按「任务 → 预测 → SQL → 结果 → 解释」组织。先手算少数几行，再让更大结果印证规律。
3. **相邻例子只换一个关键条件。** 比如外键演示同时保留父表和每种动作各一条引用。讲连接可在同一套样本对比过滤条件的位置。把正例、典型误写和修法放在同一节，让读者能指出差异发生在哪一步。
4. **把逻辑模型和实测行为写清楚。** 「先按条件配对」可用于手算，不据此断定引擎物理生成中间结果。MySQL 和 SQLite 的别名、类型、比较、写入模式要明示引擎。遇到会话选项或排序规则，写清验证前提。
5. **题目训练迁移。** 正文后的题可以依次训练直接应用、一处变化、业务边界与解释。综合篇至少保留一道需要先明确业务口径的题。不要用照抄正文就能完成的题充数。
6. **按理解成本决定篇幅。** 写全运行条件、结果和错法。重复的数据构造放到单独 SQL 文件。能一眼核对的用小表或短步骤；不必每节都有类比、固定行数或一组提示框。

推荐顺序为标题、开场问题、学习目标、准备、正文、小结、练习、下一篇。综合练习可以把小结放末尾。正文用简短二人称，提示块用 `> 💡 **重点**`、`> ⚠️ **注意**`、`> ❌ **常见错误**`。上一章已经讲过的语法，链接或一句回顾就够了。

## 分章概览与全课程图

每章从该目录的 `00_学习概览.md` 进入。概览写清本章能力、一个可从教材验证的使用场景、一张图和一个学完自检。课堂例子的运行路径图与课程图各司其职，课程图负责交代能力怎样从前面带到后面。新增或调整章节时，同步检查教材首页、上一章最后一篇的入口和全课程学习逻辑图。

## 运行路径图

在学习者容易看丢中间状态的地方加图，例如客户端发出一条查询、从行变成组、父记录变化引起级联、同一事务中提交前后看到不同结果。一篇有一张能解释关键转折的图就够；普通例题用 SQL 和结果表。优先用 Markdown 内嵌 Mermaid，和例子一起搬运、修改。

- 优先画真实会发生的状态，从输入表、关键条件或命令，走到能在 HeidiSQL 验证的行数、编号、数值或错误码。把图放在该段 SQL 旁边。
- 查询图标注为逻辑推导，读者可以据此手算结果。讲引擎实际访问顺序时，用当前环境的执行计划验证。写入图标明是哪一次连接、哪一步仍可回滚。
- 图与正文共用同一组数据。交付前渲染并逐节点核对图里的数字，然后再检查相对链接。

## 练习与折叠答案

每道题的答案紧随其后，默认收起。一题只用一个 `details`。`summary` 和正文之间、关闭标签之前留空行；SQL 围栏从行首写。折叠用浏览器原生 HTML，不依赖脚本。

````markdown
### 练习 1 · 把目标具体化

给出要完成的任务、过滤边界和所用练习表。让读者预估结果再动手。

<details>
<summary>展开参考答案</summary>

```sql
SELECT id FROM c4e_employees WHERE status = 'left' ORDER BY id;
```

结果是 5、6、7。筛选的是员工当前离职状态。

</details>
````

题干可给验收方法，例如「查出后说明边界行为什么保留」，把完整 SQL 和结果放折叠答案里。代码如果依赖已完成的题，题干标明起始状态；可独立时让每题自己恢复。预期错误写在该块首行，标明错误码和执行方式。

## 配套练习数据

- 默认沿用 `learn`。`students` 和已有章节表按现有用途使用，前置样本当只读。新章用 `c5_`、`c6_` 等前缀。需要互相隔离的写入练习可编号 `c5a_`、`c5b_`。
- 交付一份 UTF-8 安装 SQL，显式 `USE learn;`、可读的表定义和列清单、固定主键和日期。初次安装与重做分别说明。遇到同名表，先确认是同一份练习数据；用明确范围补建或恢复，不把删表混入日常入口。
- 数据集优先共用，一处维护。样本规模够手算即可，按教学目的留出空值、零条匹配、同名、并列、重复候选、日期首尾等反例。表非常大时另建性能样本。记录验收行数与一两个关键结果。
- 外键保持启用，按父表先、子表后安装，按子表先、父表后清理专用作业表。审计同名表、数据库名和作用域。备份恢复先复核数据来源。回滚写入练习默认使用显式事务，分开演示可能隐式提交的结构命令。
- SQL 只用教材表和明确范围内的数据。密码由当前环境输入。文档、命令、测试日志里不留真实密码。文件路径优先用相对路径；环境说明可给本机命令的实际路径。

## 第 05 章数据集的设计依据

优先用一个小电商数据集。客户可以没有订单，一张订单可含多条商品明细。准备一个始终没卖出的商品、一个多笔订单的客户，以及同一时间或同一金额的并列样本。商品的现价和订单行的成交价分开，营收用成交价乘数量。串联做题时，每见一次一对多都让读者手算结果会多几行，防止把明细行数叫作订单个数。若需自连接，可以用独立的极小员工表说明。

建议依次写「为什么拆表」「匹配的行怎么出来」「保留没匹配的行」「把一个查询结果拿去筛另一个结果」「把形状一致的结果上下拼起来」「综合练习」。讲外连接时实际对照 `ON` 与 `WHERE`。只有能够拒绝补出的空值的条件，放在 `WHERE` 才会排除原先保留的空行。讲全外连接模拟时用互斥的两段保留合法重复。讲子查询时用存在与否、单值、行集三种需求选语法；相关引用可按每个外层候选行来理解，引擎可重写执行。第 05 章若要出“每组前 N”或“复购”题，先定义并列规则及参与的订单状态、时间范围和分母，确保知识点在练习前出现。

## 交付前要实际核对

- 用真实引擎执行安装 SQL，以及正文和答案中的可运行 SQL。预期错误逐条执行，核验错误码。抽查正文写出的结果、排序和最常出错的边界，记录验证版本。一次通过的代码也要测试重做路径。
- 对写操作确认原始表结构与数据在演练前后相同。核对当前数据库、表名白名单、连接与事务结束状态。若动用了备份，用恢复实际数据证明副本可用。
- 检查目录、题目、答案、相对链接和下一篇。每道题有一个默认关闭的答案，里面的代码可读。用 Markdown 渲染器验证 `summary`、代码块和闭合位置。语法依赖、查看方式与错误行为都写在第一次用到的地方。
- 最后给学习者一段简短说明，列完成的文件与数据、实测情况、实际取舍和仍待验证的部分。目录入口应指向可用的正文，路线变动时同步更新前后篇链接。
