## 第 02 章 · 相同表名下换了数据

四篇正文曾反复删除并重建 `c2_employees`。其夹带的样本不同，跑哪一篇会决定下一篇能查出什么。即使语句写得正确，沿用上次的表也可能对不上答案。

| 检查点 | 原稿中出现的口径 | 当前 `learn` 统一结果 |
|---|---|---|
| 全员平均工资 | 分组开头写 14178.57，HAVING 使用过 13071.428571 | `184200 / 14 ≈ 13157.14` |
| 至少四人的部门 | HAVING 把技术部、市场部各 4 人当作基线 | 技术部与人事部各 4 人；市场部、财务部各 3 人 |
| 技术部平均工资 | HAVING 示例写 20750.00 | `81000 / 4 = 20250.00` |
| 技术部已登记奖金平均 | 分组正文写 `53000 / 3` | `87000 / 3 = 29000.00` |

已统一为现有的 14 名员工与 16 笔订单。`c2_` 样本只装一次，各篇只读。另修正三个概念。

- MySQL 允许 `GROUP BY` 和 `HAVING` 引用输出别名。逻辑顺序帮助理解结果，别名的可见性还要遵循数据库语法。
- `COUNT(*)` 数行，`COUNT(列)` 跳过空值。奖金未知时，已知总额除以全员人数，是明确的分摊口径；数据未补全时不能据此断言实际的全员奖金均值。
- `MAX(salary)` 给出最高工资数值。要找拿这个工资的人，需要另一层比较，并规定如何处理并列。第 05 章做实现。

## 三道快速自检

### 自检 1 · 找对目标

今天要查小红成绩。你在新的查询连接里没选库，如何写一条不会误查别的同名表的查询？

<details>
<summary>展开参考答案</summary>

```sql
SELECT name, score FROM learn.students WHERE id = 2;
```

题目给的是当前样本的编号 2，用全限定表名。返回小红、88.00。

</details>

### 自检 2 · 同分时会怎样

按成绩排序取前 2。如果两人同分只写 `ORDER BY score DESC`，分页为什么还可能不稳定？

<details>
<summary>展开参考答案</summary>

同分行的先后没有指定。加上 `id ASC` 打破并列。同一份数据下有唯一的顺序。两次翻页间若表内容有变化，偏移仍可能改变。

</details>

### 自检 3 · 一个组的门槛

请自己查出员工数至少为 4 的部门。写完再核对，在当前数据里市场部为什么不在？

<details>
<summary>展开参考答案</summary>

```sql
SELECT department, COUNT(*) AS employees FROM learn.c2_employees
GROUP BY department HAVING COUNT(*) >= 4 ORDER BY MIN(id);
```

技术部、人事部各 4 人，市场部 3 人。`WHERE` 先筛行，人数门槛在分组以后判断。

</details>
