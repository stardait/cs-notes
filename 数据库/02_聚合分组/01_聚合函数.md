# 第 2 章 · 聚合函数 —— 从「看明细」到「看统计」

> 前 4 篇你都在一行一行地看数据。但老板不会问「张伟多少钱」，他问的是：**一共发多少钱？平均多少？谁最高？**
>
> 聚合函数干的就是这件事：**把多行压成一行。** 从「看明细」到「看统计」，是数据库从玩具变成工具的第一步。

## 学习目标

1. 理解聚合函数「多行 → 一个值」的本质
2. 分清 `COUNT(*)` / `COUNT(列)` / `COUNT(DISTINCT 列)`
3. 用 `SUM` / `AVG` / `MAX` / `MIN` 做统计
4. **搞懂聚合函数为什么「忽略 NULL」**
5. 看穿 `AVG` 的分母陷阱
6. 用 `ROUND` 控制小数位数
7. 知道聚合函数**不能和普通列混用**、**不能写进 `WHERE`**

## 一、聚合函数是什么：多行 → 一个值

> **聚合函数不是「计算」，而是「把多行压成一行」。**

`SELECT name, salary FROM c2_employees` 进来 14 行、出去 14 行——一行对一行。聚合函数不一样：**进去 14 行，出来 1 行。**

```sql
SELECT SUM(salary) AS 工资总额 FROM c2_employees;
```

**结果：`184200.00`** —— 14 行数据，只剩 1 个数字了。

> 🍎 **生活类比**：一筐苹果，你一个个拿起来看是明细；你把整筐放秤上，**只看一个读数「12.5 公斤」**就是聚合。秤不会告诉你哪颗苹果多重，聚合函数也一样：**只给汇总值，原来的行没了。**

五个函数，一次认识：

```sql
SELECT
    COUNT(*)      AS 人数,
    SUM(salary)   AS 工资总额,
    AVG(salary)   AS 平均工资,
    MAX(salary)   AS 最高工资,
    MIN(salary)   AS 最低工资
FROM c2_employees;
```

| 人数 | 工资总额 | 平均工资 | 最高工资 | 最低工资 |
|---|---|---|---|---|
| 14 | 184200.00 | 13157.142857 | 26000.00 | 6600.00 |

**注意 `MAX` / `MIN` 返回的是那个「值」，不是那一行**——它只告诉你最高工资 26000，不会把刘洋的名字一起带出来（第七节细说）。

## 二、`COUNT` 的三种写法

> **`COUNT(*)` 数行，`COUNT(列)` 数这列有多少个值，`COUNT(DISTINCT 列)` 数有多少个不重复的值。**

一句话记忆：**星号看行，列名看值。**

```sql
SELECT COUNT(*) AS 员工总数, COUNT(bonus) AS 有奖金的人数,
       COUNT(DISTINCT department) AS 部门数
FROM c2_employees;
```

| 员工总数 | 有奖金的人数 | 部门数 |
|---|---|---|
| 14 | 10 | 4 |

**同一张表，三个不同的问题，三个不同的答案。** 逐个拆开看：

**`COUNT(*)` 数「行」：** `*` 表示整行，**不管里面有没有 NULL**，只要这行存在就算一个 → 14。

**`COUNT(列)` 数「非 NULL 的值」：** 14 行却只数出 10 个，少的 4 个是谁？

```sql
SELECT name, bonus FROM c2_employees WHERE bonus IS NULL;
```

| name | bonus |
|---|---|
| 王强 | NULL |
| 赵磊 | NULL |
| 郑霞 | NULL |
| 何雪 | NULL |

**14 - 4 = 10，对上了。**

> 💡【重点】**`COUNT(列)` 只数非 NULL 的值。** 这是它和 `COUNT(*)` 唯一的区别来源。如果这列每行都有值（比如 `NOT NULL` 的 `name`），两者结果一样；**只有存在 NULL 时才分道扬镳。**

**`COUNT(DISTINCT 列)` 数「去重后剩几个」：** 14 行里只有 4 个部门，每个部门重复出现 3~4 次 → 4。

拿奖金验一下：`SELECT COUNT(bonus), COUNT(DISTINCT bonus) FROM c2_employees;` 返回 **10 / 9**——10 个非 NULL 的奖金值里有两个 4000（吴鹏、马超），去重后只剩 9 个。

> ⚠️【注意】`DISTINCT` 写在**括号里面**：`COUNT(DISTINCT 列)` ✅，`DISTINCT COUNT(列)` ❌。
>
> 【常见错误】别拿结果反推写法。这篇数据里 14 个人的工资各不同，`COUNT(salary)` 和 `COUNT(DISTINCT salary)` 都是 14——**纯属巧合**。判断依据永远是「你要数人还是数种类」，不是「结果碰巧相同」。

## 三、`SUM` / `AVG` / `MAX` / `MIN`

> **`SUM` 加起来，`AVG` 平均，`MAX` 最大，`MIN` 最小——全部只认「非 NULL 的值」。**

```sql
SELECT
    SUM(bonus) AS 奖金总额,
    AVG(bonus) AS 平均奖金,
    MAX(bonus) AS 最高奖金,
    MIN(bonus) AS 最低奖金
FROM c2_employees;
```

| 奖金总额 | 平均奖金 | 最高奖金 | 最低奖金 |
|---|---|---|---|
| 131000.00 | 13100.000000 | 45000.00 | 2000.00 |

最高的 45000 是刘洋（技术部），最低的 2000 是冯涛（2024 年才入职）。**奖金总额 131000 是 10 个人加出来的，不是 14 个**——下一节专门讲这个。

`MAX` / `MIN` 也能用在年份上：

```sql
SELECT MAX(hire_year) AS 最晚入职年份, MIN(hire_year) AS 最早入职年份 FROM c2_employees;
```

**结果：`2024` / `2015`** —— 2024 年的冯涛是新人，2015 年的郑霞是老员工。

> ⚠️【注意】`MAX` / `MIN` 对中文也能算（按 UTF-8 字节比大小，不是拼音），但**结果没有业务意义**，日常统计只对数字和日期用。

### 聚合结果可以继续参与运算

`SELECT SUM(salary * 12), MAX(salary) - MIN(salary) FROM c2_employees;` 返回 **2210400.00 / 19400.00**。

`SUM(salary * 12)` 是「先给每行乘 12，再加起来」，等价于 `SUM(salary) * 12`；`19400 = 26000 - 6600`，就是最高和最低的差距。

> 💡【重点】聚合函数的结果是**普通数值**，可以继续参与算术：`MAX - MIN`、`SUM / COUNT`、`AVG * 12` 都合法且常用。

## 四、🔴 聚合函数忽略 NULL（重点中的重点）

> **聚合函数处理时，会把 NULL 的行「跳过」，不是当成 0。**

这一句是本章的地基。**理解它，后面所有坑全部自动通关。**

```sql
SELECT SUM(bonus) AS 奖金总额, COUNT(bonus) AS 参与计算的人数 FROM c2_employees;
```

| 奖金总额 | 参与计算的人数 |
|---|---|
| 131000.00 | 10 |

**131000 是 10 个人加出来的，不是 14 个。** 如果 NULL 被当成 0，加进去也不影响总额——所以 `SUM` **看不出**区别。但 `AVG` 看得出来：

```sql
SELECT AVG(bonus) AS 平均奖金 FROM c2_employees;
```

**结果：`13100.000000`** —— **验算：`131000 / 10 = 13100`，分母是 10，不是 14。**

> 💡【重点】**「忽略 NULL」的确切含义：** `SUM` 跳过 NULL 只加非 NULL 的 10 个；`AVG` 跳过 NULL、**分母也是 10**；`COUNT(bonus)` 数出 10；`MAX` / `MIN` 在 10 个值里找最大最小。**所有聚合函数都是这个规则，一个不例外。**

| 函数 | 若把 NULL 当 0 | 实际（跳过 NULL） | 一样吗 |
|---|---|---|---|
| `SUM(bonus)` | 131000 | 131000 | ✅ 一样（加 0 没影响） |
| `AVG(bonus)` | 131000 / 14 ≈ 9357 | 131000 / 10 = 13100 | ❌ **不一样** |
| `COUNT(bonus)` | 14 | 10 | ❌ **不一样** |
| `MAX` / `MIN` | 45000 / **0** | 45000 / **2000** | ❌ **不一样** |

> ⚠️【常见错误】很多人第一反应是「NULL 当 0 处理不就完了」。**不行。** 王强的奖金是 NULL，意思是「**我们不知道**」——可能没发，可能还没定，可能是数据没录。你把它当 0，平均奖金就变成 9357，**把一个不存在的 0 平均进去了**。数据库对 NULL 的态度是：**不知道的事，别假装知道。**

所以统计要「总额 + 人数」一起给：`SELECT COUNT(*), COUNT(bonus), SUM(bonus) FROM c2_employees;` 返回 **14 / 10 / 131000.00**——「14 个人里 10 个人有奖金，一共发了 13.1 万」，这才是完整的统计。

## 五、🔴 `AVG` 的分母陷阱

> **`AVG(列)` 的分母是「非 NULL 的行数」，不是「总行数」。**

**需求**：算出「全公司平均每人的奖金」。两种写法，两个结果：

```sql
SELECT
    SUM(bonus) / COUNT(*)  AS 除以总人数,
    AVG(bonus)             AS 除以有奖金人数
FROM c2_employees;
```

| 除以总人数 | 除以有奖金人数 |
|---|---|
| 9357.142857 | 13100.000000 |

**`131000 / 14 = 9357.14`**，**`131000 / 10 = 13100`**。相差 3743 元——同一个需求，两个答案。因为「人均奖金」本身有歧义：

```
口径 A：13.1 万分给全部 14 个人（没拿奖金的按 0 摊）→ 131000 / 14 = 9357.14   「全公司人均」
口径 B：只在 10 个拿到奖金的人里平均            → 131000 / 10 = 13100    「有奖金的人的平均」
```

> 💡【重点】**这两个数都没错，错的是它们回答的不是同一个问题。** 要「**全公司**人均」→ `SUM(列) / COUNT(*)`；要「**有该值的人**平均」→ `AVG(列)`。**`AVG` 默认走口径 B**，因为聚合函数忽略 NULL。

> 🧾 **生活类比**：14 个人去吃自助。**10 个人点了一道 328 元的硬菜，另外 4 个人没点。** 问「人均吃了多少钱的硬菜」——`AVG` 说 328（只算点菜的人），`SUM / 总人数` 说 234.29（把没点的人也摊进去）。**两种都合理，看你问的是什么。**

加上 `ROUND` 一起输出，写报告最不容易被追问：`SELECT ROUND(SUM(bonus)/COUNT(*), 2), ROUND(AVG(bonus), 2) FROM c2_employees;` 返回 **9357.14 / 13100.00**。

**`salary` 没有 NULL，所以两种写法一样**——差别只在有 NULL 时才暴露（`AVG(salary)` 和 `SUM(salary) / COUNT(*)` 都是 `13157.14`）。

> ⚠️【注意】这正是最危险的地方：**测试时数据没 NULL，上线后有了 NULL，数字就悄悄变了。**

## 六、`ROUND`：让小数不那么难看

> **`ROUND(要处理的数, 保留几位小数)`——它只改「显示」，不改「存储」。**

`AVG(salary)` 原样是 `13157.142857`，小数点后 6 位，写进周报老板会问「后面那串是什么」。包一层 `ROUND` 就清爽了：

```sql
SELECT
    ROUND(AVG(salary), 0) AS 取整,
    ROUND(AVG(salary), 1) AS 一位小数,
    ROUND(AVG(salary), 2) AS 两位小数
FROM c2_employees;
```

| 取整 | 一位小数 | 两位小数 |
|---|---|---|
| 13157 | 13157.1 | 13157.14 |

第二个参数是保留几位：`0` 适合人数、件数等大数；`1` 看趋势；**`2` 适合金额、工资（推荐）**。

> 💡【重点】钱相关统一保留 2 位。财报上的数字都是两位：**分**是人民币最小单位，再多的位数没有意义。

### 顺序很重要：先算，后 `ROUND`

`SELECT ROUND(AVG(salary), 2), ROUND(AVG(salary) * 12, 2) FROM c2_employees;` 返回 **13157.14 / 157885.71**。

**`13157.14 × 12 = 157885.68`，但结果是 `157885.71`**——因为 `AVG` 真实值是 `13157.142857...`，**乘 12 用的是没断尾巴的原始值**，最后才 `ROUND`。

> ⚠️【注意】**`ROUND` 永远是最后一步**：`ROUND(AVG(salary), 2) * 12` = `157885.68`（有误差），`ROUND(AVG(salary) * 12, 2)` = `157885.71`（准确）。

## 七、🔴 聚合函数不能和普通列混用

> **聚合函数把 14 行压成 1 行；普通列有 14 个值——1 个格子放不下 14 个值。**

我猜你想这么写：每人名字 + 平均工资。

```sql
SELECT name, AVG(salary) AS 平均工资 FROM c2_employees;
```

**报错**（MySQL 8 默认配置）：

```
ERROR 1140 (42000): In aggregated query without GROUP BY,
expression #1 of SELECT list contains nonaggregated column
'learn.c2_employees.name'; this is incompatible with
sql_mode=only_full_group_by
```

**翻译**：你用了聚合函数（结果只有 1 行），但 `SELECT` 里又写了 `name`（它有 14 个值）——**MySQL 不知道该把哪个 `name` 放进唯一的那一行里**，于是拒绝执行。

> 🧮 **生活类比**：你统计出全班平均分「82.5」，这是**一个班**的数据。现在要求你把这个数字和**某一位同学的名字**并排写在一行——那位同学是谁？不说清楚就没法写。

**要「每人的平均工资」逻辑上根本不成立**（每个人只有一个工资，平均就是他自己）。你多半要按部门算：

```sql
SELECT department, AVG(salary) AS 平均工资
FROM c2_employees
GROUP BY department;
```

| department | 平均工资 |
|---|---|
| 技术部 | 20250.000000 |
| 市场部 | 11833.333333 |
| 财务部 | 11933.333333 |
| 人事部 | 7975.000000 |

**这就是下一篇 `GROUP BY` 的内容。** 现在只要记住：

> 💡【重点】**`SELECT` 里的普通列必须和聚合的「统计单位」对齐**：只要全公司一个统计值 → `SELECT` 里**只能有聚合函数**；要每个部门一个统计值 → **加 `GROUP BY department`**。**没有第三条路。**

### 那关掉严格模式会怎样

有些旧教程里这条 SQL「能跑」，因为关了 `ONLY_FULL_GROUP_BY`。此时 MySQL **随便挑一行**的 `name` 给你：

```sql
-- 仅用于演示：先执行 SET SESSION sql_mode = '';
SELECT name, AVG(salary) AS 平均工资 FROM c2_employees;
```

执行后返回 **张伟 / 13157.142857**——它给了「张伟」，不是因为张伟特殊，只是因为他是第一行。

> ⚠️【常见错误】看到这种「能跑」的结果就以为写对了，是新手最危险的错觉。**语义是错的**，数据换顺序、升个版本、换个服务器，结果就变。**永远不要在聚合查询里混入没分组的普通列。**

## 八、🔴 `WHERE` 里不能用聚合函数

> **`WHERE` 是「筛行」，那时还没分组、还没聚合——聚合函数根本还没开始算，所以用不了。**

**需求**：找出「工资高于平均工资」的人。直觉写法：

```sql
SELECT name, salary FROM c2_employees WHERE salary > AVG(salary);
```

```
ERROR 1111 (HY000): Invalid use of group function
```

**为什么？** 执行顺序是 `FROM → WHERE → GROUP BY → HAVING → SELECT`。`WHERE` 排第 2 步，聚合要到分组之后才有意义。`WHERE` 正在一行一行筛数据时，你问它「这行工资大于平均工资吗」——**「平均工资」这个数此刻还不存在**，它得等所有行看完才能算出来。

> 🧾 **生活类比**：体检报告上有「你的指标高于全公司平均值」。这个结论必须等**所有人的体检都做完**才能出。你不可能在「给第 3 个人抽血」时就知道全公司平均值——**`WHERE` 就是那个「正在抽血」的阶段。**

**那这个需求怎么做？** 用 `HAVING` 只能得到聚合结果本身：`SELECT AVG(salary) FROM c2_employees HAVING AVG(salary) > 10000;` 返回 `13157.142857`。**`HAVING` 过滤的是「分组结果」，不是「每一行」**，所以拿不到具体哪些人。要拿到人，得用子查询（后面会细讲）：

```sql
SELECT name, salary FROM c2_employees
WHERE salary > (SELECT AVG(salary) FROM c2_employees)
ORDER BY salary;
```

| name | salary |
|---|---|
| 孙丽 | 14000.00 |
| 王强 | 15000.00 |
| 郑霞 | 16000.00 |
| 李娜 | 18000.00 |
| 张伟 | 22000.00 |
| 刘洋 | 26000.00 |

**6 个人高于平均 13157.14。** 思路：**先让括号里的子查询算出平均值（一个具体数字），`WHERE` 拿这个数字去比**——这样 `WHERE` 执行时就有数可用了。

> 💡【重点】记住三条位置规则：

| 位置 | 能用聚合吗 | 为什么 |
|---|---|---|
| `WHERE` | ❌ | 还没分组，聚合算不了 |
| `HAVING` | ✅ | 分组之后，专为过滤聚合结果而生 |
| `SELECT` | ✅ | 输出统计值，这是它的本职工作 |

> ⚠️【注意】有些教程提到 `misuse of aggregate` 这个报错——那是 **SQLite 等数据库**的措辞。MySQL 报的是 `Invalid use of group function`，**意思完全一样**。看到 1111，就是同一个问题。

## 九、本章小结

> **聚合函数把多行压成一行，统计时忽略 NULL。**

| 函数 | 作用 | 忽略 NULL | 空集返回 |
|---|---|---|---|
| `COUNT(*)` | 数行数 | 不忽略（数行） | `0` |
| `COUNT(列)` | 数非 NULL 值 | 忽略 | `0` |
| `COUNT(DISTINCT 列)` | 数不重复的非 NULL 值 | 忽略 | `0` |
| `SUM(列)` | 求和 | 忽略 | `NULL` |
| `AVG(列)` | 平均 | 忽略（**分母也少**） | `NULL` |
| `MAX` / `MIN` | 最大 / 最小 | 忽略 | `NULL` |

**三个必背的坑：**

1. **`COUNT(*)` ≠ `COUNT(列)`**：14 行 vs 10 个非 NULL 值
2. **`AVG` 的分母不是总行数**：`131000 / 10 = 13100`，而 `SUM / COUNT(*)` 是 `9357.14`——两个都对，回答的是不同问题
3. **聚合不能和普通列混用**：`SELECT name, AVG(salary)` 报 1140，要么去掉 `name`，要么 `GROUP BY`

## 参考答案

> 先自己写，写完再对照。**别急着看——先写，再看。**

### 答案 1

```sql
SELECT COUNT(*) AS 总人数, ROUND(AVG(salary), 2) AS 平均工资 FROM c2_employees;
```

**结果：`14` / `13157.14`**。`salary` 列没有 NULL，所以 `AVG` 的分母就是总人数 14。

### 答案 2

```sql
SELECT
    SUM(salary)               AS 工资总额,
    MAX(salary)               AS 最高工资,
    MIN(salary)               AS 最低工资,
    MAX(salary) - MIN(salary) AS 极差
FROM c2_employees;
```

**结果：`184200.00` / `26000.00` / `6600.00` / `19400.00`**。关键点：`MAX - MIN` 是两个聚合函数相减，结果是普通数值，可以直接放进 `SELECT`。

### 答案 3

```sql
SELECT COUNT(bonus) AS 有奖金人数, SUM(bonus) AS 奖金总额 FROM c2_employees;
```

**结果：`10` / `131000.00`**。**陷阱**：必须用 `COUNT(bonus)`，不能用 `COUNT(*)`——后者会数出 14，把那 4 个没拿奖金的也算进「有奖金人数」里了。

### 答案 4

```sql
SELECT
    COUNT(DISTINCT bonus)       AS 奖金档位数,
    COUNT(DISTINCT department)  AS 部门数
FROM c2_employees;
```

**结果：`9` / `4`**。10 个人拿奖金，但 `4000` 出现了两次（吴鹏、马超），去重后是 9 种；部门 4 个，每个重复出现 3~4 次。`COUNT(DISTINCT 列)` 同样忽略 NULL，那 4 个 NULL 不算一个档位。

### 答案 5

`AVG(bonus)` 返回 **`13100.000000`**，`SUM(bonus) / COUNT(*)` 返回 **`9357.142857`**。

**为什么不一样？**

- **前者分母是 10**：`AVG` 忽略 NULL，只用 10 个非 NULL 的值平均 → `131000 / 10 = 13100`
- **后者分母是 14**：`COUNT(*)` 数的是总行数 → `131000 / 14 ≈ 9357`

**这不是 bug，是两种统计口径**：前者回答「有奖金的人平均拿多少」，后者回答「全公司平均每人拿到多少（没拿的按 0 摊）」。**报告里最好两个都写，并注明口径。**

### 答案 6

报错：

```
ERROR 1140 (42000): In aggregated query without GROUP BY,
expression #1 of SELECT list contains nonaggregated column
'learn.c2_employees.name'; this is incompatible with
sql_mode=only_full_group_by
```

**错在哪**：`AVG(salary)` 把 14 行压成 1 行，`name` 却是普通列（14 个值）。**1 个格子放不下 14 个名字**，MySQL 不知道该显示谁。

**怎么改**：看真实需求——只要全公司平均工资，就删掉 `name`：

```sql
SELECT AVG(salary) AS 平均工资 FROM c2_employees;
```

要每个部门一个平均工资，就加 `GROUP BY`（下一篇学）：`SELECT department, AVG(salary) FROM c2_employees GROUP BY department;`。

**核心判断法**：问自己——**「这个普通列，每行只有一个值吗？」** 是，它能和聚合共存（比如 `GROUP BY` 的列）；不是，它必须从 `SELECT` 里去掉，或者加 `GROUP BY`。

> 📌 **最后叮嘱**：聚合函数的知识点不难，难的是「NULL 会不会参与计算」这种细节——**只有亲手跑一遍，看到 `COUNT(*)` 和 `COUNT(bonus)` 差 4，你才算真的懂了。**
