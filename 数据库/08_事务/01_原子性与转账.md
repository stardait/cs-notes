# 第 08 章 · 原子性与转账

> 转账由扣款和入账组成。两条语句中任何一步没发生，余额都应该回到转账前。

## 学习目标

- 把相关写入放进同一个事务，按受影响行数决定下一步。
- 说清原子性、一致性、隔离性与持久性分别检查什么。

## 准备

使用 InnoDB 的 `c8_accounts`。缺表时运行[配套 SQL](00_安装配套表.sql)。起始余额：1 号 1000.00，2 号 500.00，3 号 200.00。先确认自己的样本是这个状态。
```sql
USE learn;
SELECT id, name, balance FROM c8_accounts ORDER BY id;
```

## 一、先演示一次能回滚的转账

准备模拟从 1 号转 200 给 2 号。下面两块 SQL 在同一个查询连接，逐块运行。扣款在同一句里判断余额，避免先读后改之间的竞态。

```sql
START TRANSACTION;
UPDATE c8_accounts
SET balance = balance - 200
WHERE id = 1 AND balance >= 200;
SELECT ROW_COUNT() AS debited;
```

结果 `debited` 应为 1。只有看到 1 才执行下一块，否则在同一连接运行 `ROLLBACK;` 后停止。`ROW_COUNT()` 应紧跟对应的写入，插入其他查询会改变它要看的对象。

```sql
UPDATE c8_accounts SET balance = balance + 200 WHERE id = 2;
SELECT ROW_COUNT() AS credited;
SELECT id, balance FROM c8_accounts WHERE id IN (1, 2) ORDER BY id;
SELECT SUM(balance) AS total FROM c8_accounts WHERE id IN (1, 2);
```

入账 1 行，两边变成 800.00、700.00，合计仍 1500.00。这个连接能读到自己的改动，此时还处在事务中。练习结束回滚，再读一次。

```sql
ROLLBACK;
SELECT id, balance FROM c8_accounts WHERE id IN (1, 2) ORDER BY id;
```

回到 1000.00、500.00。真实转账必须在「扣款一行、收款一行、所有检查通过」后才提交。实际业务还有转账号、防重规则与流水，本课只演示余额上的原子性。

## 二、故意让第二步找不到收款人

```sql
START TRANSACTION;
UPDATE c8_accounts SET balance = balance - 200 WHERE id = 1 AND balance >= 200;
SELECT ROW_COUNT() AS debited;
UPDATE c8_accounts SET balance = balance + 200 WHERE id = 999;
SELECT ROW_COUNT() AS credited;
ROLLBACK;
SELECT id, balance FROM c8_accounts WHERE id = 1;
```

入账匹配 0 行通常不会报错。单看客户端有没有红色错误，会误把失败当成功。完整结果是扣款 1 行、入账 0 行、回滚后 1 号仍为 1000.00。也不要依赖「一个语句报错会撤回整笔事务」。有些错误只撤回该语句，所以失败时主动回滚整个业务事务。

## 三、用同一笔转账理解 ACID

| 特性 | 这笔转账要问什么 |
|---|---|
| 原子性 Atomicity | 扣款和入账能否一起成功或一起撤回 |
| 一致性 Consistency | 转账前后的规则是否都成立，例如余额非负、合计守恒 |
| 隔离性 Isolation | 并发的其他连接在各时刻能看到哪些数据 |
| 持久性 Durability | 已提交的结果在正常恢复后能否保留 |

表上的 `CHECK` 可挡住负余额。检查合计与不能给自己转账等业务规则需要由事务中的逻辑保证。自动提交开启时，每条语句通常各自提交，因此要在第一条写入前明确开启事务。普通 DDL 可能隐式提交；转账事务只放这次业务所需的语句。可查 [MySQL COMMIT 和 ROLLBACK](https://dev.mysql.com/doc/refman/26.10/en/commit.html)。

## 小结

每次业务事务先界定成功条件。条件失败，撤回整个业务操作；检查都通过，再确定提交。
