# 第 03 章 · 数据类型

> 选类型时先问三件事。这个值拿来算还是展示，需要多精确，允许多大范围？

## 学习目标

- 给计数、金额、手机号、日期和状态选类型，并解释取舍。
- 用实际结果区分十进制精确数和近似数。
- 预测超长、越界和缺失值怎么表现，知道该检查哪项设置。

## 准备

```sql

```

本机验证启用了严格模式。报错演示按这个环境写。本篇写数据的短实验用 `START TRANSACTION` 和 `ROLLBACK` 把临时写入收回，选中整块执行即可。第 04 章会再练。

## 一、整数按范围选

| 类型 | 字节数 | 有符号范围 | `UNSIGNED` 范围 |
|---|---:|---|---|
| `TINYINT` | 1 | −128 ～ 127 | 0 ～ 255 |
| `SMALLINT` | 2 | −32,768 ～ 32,767 | 0 ～ 65,535 |
| `INT` | 4 | −2,147,483,648 ～ 2,147,483,647 | 0 ～ 4,294,967,295 |
| `BIGINT` | 8 | −9,223,372,036,854,775,808 ～ 9,223,372,036,854,775,807 | 0 ～ 18,446,744,073,709,551,615 |

年龄存整年时，用 `TINYINT UNSIGNED` 就够了。但是 240 仍然装得下。类型管的是值能否表示，业务上限另加 `CHECK`。一般练习表编号用 `INT` 足够，预估长期编号会超过上限时再用 `BIGINT`。如果之后有引用这列的外键，整数的类型和有无符号也要对齐。

```sql
-- 预期错误 1264
INSERT INTO c3b_type_samples (id, age) VALUES (90, 300);
```

`UNSIGNED` 把负数的范围分给了正数。在 MySQL 中，无符号整数算减法也可能因结果为负而报错。要表示欠款、温差或带正负的库存调整量，先确认业务允许的范围。

## 二、钱用 DECIMAL

`DECIMAL(10,2)` 的 10 是**总位数**，2 是**小数位数**，所以整数部分最多 8 位，上限是 `99999999.99`。符号和小数点不占位。单价、余额、工资等需要精确对账的金额可用 `DECIMAL`。`FLOAT` 和 `DOUBLE` 保存二进制近似值，`DOUBLE` 精度较高，适合允许近似的测量或统计数据。

先预测三个布尔结果，再执行。带 `E0` 的字面量是近似数。

```sql
SELECT 0.1 + 0.2 = 0.3 AS decimal_equal,
       0.1E0 + 0.2E0 = 0.3E0 AS approximate_equal,
       CAST(0.1E0 + 0.2E0 AS DECIMAL(20,18)) AS approximate_sum;
```

本机结果分别是 `1`、`0`、`0.300000000000000040`。第三列保留足够多的小数位，能看到偏差。再比较一笔金额放大 100 次的结果。

```sql
SELECT exact_amount * 100 AS decimal_total,
       CAST(float_amount AS DOUBLE) * 100 AS float_total
FROM c3b_type_samples
WHERE id = 1;
```

`decimal_total` 是 `10.00`，`float_total` 约为 `10.000000149`。金额小、笔数少时，差值可能显示不出来。下面展示一笔较大的金额，单笔开始就已经丢了分。

```sql
START TRANSACTION;
INSERT INTO c3b_type_samples (id, exact_amount, float_amount, double_amount)
VALUES (91, 1000000.01, 1000000.01, 1000000.01);
SELECT exact_amount, CAST(float_amount AS DOUBLE) AS float_stored,
       (exact_amount - CAST(float_amount AS DOUBLE)) * 100 AS loss_per_100
FROM c3b_type_samples WHERE id = 91;
ROLLBACK;
```

`exact_amount` 是 `1000000.01`，`float_stored` 是 `1000000`，按存下来的一笔乘 100，差额约为 1 元。后面 `ROUND` 能决定显示或业务舍入的位数，无法补回写入时丢掉的精度。金额需要舍入时仍要确认业务规则，例如按每笔舍入还是汇总后舍入。

## 三、文本按含义选

| 类型 | 什么时候用 | 例子 |
|---|---|---|
| `CHAR(n)` | 格式的字符数固定 | `CHAR(2)` 保存两字母国家代码 |
| `VARCHAR(n)` | 长度变化，业务可定义上限 | `VARCHAR(20)` 保存手机号或代号 |
| `TEXT` | 内容可能较长 | 简介、评论 |

`VARCHAR(20)` 的 20 是字符数。字符集会影响实际字节数。下面比较同一个手机号和两个汉字。

```sql
SELECT phone, CAST(phone AS UNSIGNED) AS as_number,
       CHAR_LENGTH('林青') AS chars, LENGTH('林青') AS bytes
FROM c3b_type_samples WHERE id = 1;
```

| phone | as_number | chars | bytes |
|---|---:|---:|---:|
| 01234567890 | 1234567890 | 2 | 6 |

电话可能带前导零、国际区号、分机号，通常按文本保存。`CHAR(2)` 也只是存储类型。如果必须是两位大写字母，需另加校验。`VARCHAR` 的上限应来自业务及数据验证，不同列可以各有长度。

```sql
-- 预期错误 1406
INSERT INTO c3b_type_samples (id, phone)
VALUES (92, '一二三四五六七八九十一二三四五六七八九十一');
```

上面 21 个字符要挤进 20 字符的列。本机普通写入报 `1406`。较宽松的模式或某些带 `IGNORE` 的写入可能截断并产生警告。数据少字同样需要排查。

## 四、先问你要保存哪种时间

| 类型 | 适合存什么 | 例子 |
|---|---|---|
| `DATE` | 只要日期 | 生日、入职日 |
| `TIME` | 一天中的时刻或有界的时长 | `09:00:00`、`26:30:00` |
| `DATETIME` | 保存输入的年月日时分秒，范围约公元 1000 至 9999 年 | 门店当地时间预约 |
| `TIMESTAMP` | 按当前连接时区解释输入，转 UTC 存储，读取时转换回当前连接时区 | 记录业务事件发生的时刻，需留意 2038 年上限 |

先用 UTC 查看，再把**当前连接**的时区改为 `+08:00`。整段在同一个查询标签执行，最后会恢复原设置。

```sql
SET @c3_original_time_zone = @@session.time_zone;
SET SESSION time_zone = '+00:00';
SELECT joined_on, elapsed, local_at, recorded_at FROM c3b_type_samples WHERE id = 1;
SET SESSION time_zone = '+08:00';
SELECT joined_on, elapsed, local_at, recorded_at FROM c3b_type_samples WHERE id = 1;
SET SESSION time_zone = @c3_original_time_zone;
```

`joined_on` 是 `2026-10-01`，`elapsed` 是 `26:30:00`。`local_at` 两次都是 `2026-10-01 09:00:00`，`recorded_at` 会由 `09:00:00` 变为 `17:00:00`（同一天）。若要长期保存超出 `TIMESTAMP` 范围的绝对时刻，可以用 `DATETIME` 并在应用和数据约定里明确存 UTC、如何转换。`DEFAULT CURRENT_TIMESTAMP` 两种类型都能用，写入时省略该列就能记录当前时间。

## 五、值的集合与缺失

`ENUM('pending','approved')` 把取值限定到这组文本，适合变化少的小集合。以后常加状态的系统要考虑变更成本。`BOOLEAN` 在 MySQL 是 `TINYINT(1)` 的同义词，`TRUE` 和 `FALSE` 是 `1` 和 `0`。如果业务只接受这两个值，需要另加 `CHECK (enabled IN (0, 1))`，必填时再加 `NOT NULL`。

下面把缺失、空字符串和真的有内容区分开。

```sql
SELECT id, phone, phone IS NULL AS is_missing,
       CHAR_LENGTH(phone) AS phone_length, state, enabled
FROM c3b_type_samples ORDER BY id;
```

`id=1` 有 11 字符手机号，`id=2` 的电话是 `NULL`，长度也是 `NULL`。`id=3` 有一个长度为 0 的字符串。后两行在某些界面都看着像空白，`IS NULL` 的结果只有第 2 行是 `1`。

## 小结

把类型选择变成一句可检验的话。例如「手机号要保留每个字符，最长 20 字符，因此用 `VARCHAR(20)`」。再挑一个边界值测试，比背类型名更容易判断设计是否合适。

## 动手练习

### 练习 1 · 存单价和数量

订单单价最高 300 万元，保留到分。数量 1 到 10,000 件。给两列各选一个够用的类型。

<details>
<summary>展开参考答案</summary>

单价可以用 `DECIMAL(9,2)`，可存 7 位整数和 2 位小数。数量可用 `SMALLINT UNSIGNED`。数量的 `1～10000` 是业务范围，类型以外再加 `CHECK`。

</details>

### 练习 2 · 找未录入电话的人

用现有样本，各写一条语句找出「未录入」和「明确存了空字符串」的行。

<details>
<summary>展开参考答案</summary>

```sql
SELECT id FROM c3b_type_samples WHERE phone IS NULL;
SELECT id FROM c3b_type_samples WHERE phone = '';
```

第一条返回 `2`，第二条返回 `3`。

</details>

### 练习 3 · 判断该存什么时间

你做的是跨城市活动报名。A 列存报名成功的时刻，B 列存各门店填报的当地预约时间。给两列选类型，写出前提。

<details>
<summary>展开参考答案</summary>

A 可选 `TIMESTAMP`，前提是范围覆盖使用期限且你能管理连接时区。B 可用 `DATETIME` 保存门店填入的钟表时间。如果还要据此通知或跨门店比较，另存门店时区或明确转换规则。

</details>

以上类型和模式均以 MySQL 为准。SQLite 的类型和约束行为会在后续单独实测。可查 [MySQL 数据类型手册](https://dev.mysql.com/doc/refman/26.10/en/data-types.html)和 [DATE、DATETIME 与 TIMESTAMP](https://dev.mysql.com/doc/refman/26.10/en/datetime.html)。
