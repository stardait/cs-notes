# 第 03 章 · 约束

> 先找出一条绝对不能破坏的业务规则，再决定让数据库用哪种约束守住它。

## 学习目标

- 为一张报名表选择主键、必填项、唯一项、默认值和取值范围。
- 预测重复值、缺省值、`NULL` 和越界值各自会发生什么。
- 用成功案例与失败案例验收约束，用主键定位记录而不依赖编号连续。

## 准备

本篇使用 `c3c_registrations`。选择下面代码执行，基线有 3 行。

```sql
USE learn;
SELECT id, registration_no, name, email, score, status
FROM c3c_registrations ORDER BY id;
SHOW CREATE TABLE c3c_registrations;
```

| id | registration_no | name | email | score | status |
|---:|---|---|---|---:|---|
| 1 | R001 | 林青 | lin@example.test | 86.50 | approved |
| 2 | R002 | 周宁 | NULL | NULL | pending |
| 3 | R003 | 陈禾 | NULL | 73.00 | pending |

下面带「预期错误」的语句各自单独执行。预期报错意味着数据库守住了这条规则。成功的试插用 `ROLLBACK` 收回记录，编号计数可能变化。

## 一、主键负责定位

两人可以叫同一个名字。报名系统每次却要找到某一条报名记录，这就是 `PRIMARY KEY` 的工作。主键的值唯一且非空。一张表最多声明一个主键，它可以由一列组成，也可以由多列组成。

```sql
-- 预期错误 1062
INSERT INTO c3c_registrations (id, registration_no, name)
VALUES (1, 'R900', '王云');
```

报名号换了，`id=1` 仍然和现有主键冲突。多列主键约束的是**完整组合**。比如同一份报名可能提交多版，每个报名的第 1 版允许同时存在，重复的「同一报名 + 同一版本」应拒绝。下面用独立的结构练习表观察组合主键。

```sql
CREATE TABLE c3c_revision_lab (
    registration_id INT NOT NULL,
    revision_no INT NOT NULL,
    PRIMARY KEY (registration_id, revision_no)
);
INSERT INTO c3c_revision_lab (registration_id, revision_no)
VALUES (1, 1), (1, 2), (2, 1);
SELECT registration_id, revision_no FROM c3c_revision_lab
ORDER BY registration_id, revision_no;
```

```sql
-- 预期错误 1062
INSERT INTO c3c_revision_lab (registration_id, revision_no) VALUES (1, 2);
```

```sql
DROP TABLE c3c_revision_lab;
```

> 💡 **重点** MySQL 技术上允许普通表没有显式主键。业务表通常主动声明主键，让读取、更新、关联时能明确定位一行。

## 二、自增负责发编号

`AUTO_INCREMENT` 像发号机。省略自增列时，MySQL 分配一个编号。在 InnoDB 的常规设计里，把它放在整数主键上最直接。就 MySQL 的要求而言，自增列应为整数索引列，InnoDB 要求它位于某个索引的第一列。每张表最多一个自增列。

在另一张演示表里试发号。先得 1 与 2，删除 2 后下一次领到 3。

```sql
CREATE TABLE c3c_number_lab (
    id INT PRIMARY KEY AUTO_INCREMENT,
    label VARCHAR(20) NOT NULL
) ENGINE=InnoDB;
INSERT INTO c3c_number_lab (label) VALUES ('甲'), ('乙');
DELETE FROM c3c_number_lab WHERE id = 2;
INSERT INTO c3c_number_lab (label) VALUES ('丙');
SELECT id, label FROM c3c_number_lab ORDER BY id;
SHOW CREATE TABLE c3c_number_lab;
```

表里只剩 `id=1` 和 `id=3`。`SHOW CREATE TABLE` 的表选项通常显示下一次分配值，本例在默认步长下是 `AUTO_INCREMENT=4`。可以在这张演示表中把下一次发号提高到 20。

```sql
ALTER TABLE c3c_number_lab AUTO_INCREMENT = 20;
INSERT INTO c3c_number_lab (label) VALUES ('丁');
SELECT id, label FROM c3c_number_lab ORDER BY id;
DROP TABLE c3c_number_lab;
```

表中最后新增的是 `id=20`。自增值不能靠任意指定一个较小数来覆盖已有编号。失败写入、回滚、并发或批量分配都可能留下空档。统计报名人数用 `COUNT(*)`，不要用最大的 `id`。

## 三、四类规则各守一件事

| 规则 | 在报名表里的用途 | 写入时怎么检查 |
|---|---|---|
| `NOT NULL` | 姓名必须有值 | 拒绝 SQL 的 `NULL` |
| `UNIQUE` | 报名号唯一，填了邮箱则邮箱也应唯一 | 拒绝键值重复，允许多个 `NULL` |
| `DEFAULT` | 初次报名默认待审核并记录创建时间 | 省略列或显式写 `DEFAULT` 时填入默认值 |
| `CHECK` | 成绩必须在 0 至 100 内 | 表达式为假时拒绝写入 |

一张表可以有多个唯一约束。比如报名号与邮箱分别查重。想表达「必填且唯一」，就像报名号一样同时声明 `NOT NULL UNIQUE`。`NOT NULL` 只防 SQL 空值，空字符串仍是一个值。想拒绝全空白的姓名，要另写清楚规则。

先试一次最简报名。注意没写邮箱、成绩、状态和创建时间。

```sql
START TRANSACTION;
INSERT INTO c3c_registrations (registration_no, name) VALUES ('R004', '赵星');
SELECT registration_no, email, score, status, created_at IS NOT NULL AS has_time
FROM c3c_registrations WHERE registration_no = 'R004';
ROLLBACK;
```

预期返回 `R004, NULL, NULL, pending, 1`。对普通可空列，省略 `DEFAULT` 时，MySQL 通常把默认值设为 `NULL`。对必填列，`NOT NULL` 又没有可用默认值时，严格模式下省略该列会得到 `1364`。显式传 `NULL` 是你主动提供的值，也不能替必填列触发默认逻辑。

```sql
-- 预期错误 1364
INSERT INTO c3c_registrations (registration_no) VALUES ('R005');
```

```sql
-- 预期错误 1048
INSERT INTO c3c_registrations (registration_no, name) VALUES ('R005', NULL);
```

```sql
-- 预期错误 1062
INSERT INTO c3c_registrations (registration_no, name, email)
VALUES ('R005', '王云', 'lin@example.test');
```

## 四、用失败样本检验 CHECK

`CHECK (score BETWEEN 0 AND 100)` 能挡住 `101` 和 `-1`。本表允许成绩暂缺。`NULL BETWEEN 0 AND 100` 的结果是未知，MySQL 的 `CHECK` 允许这类结果通过。若成绩必须填写，同时声明 `NOT NULL`。

```sql
-- 预期错误 3819
INSERT INTO c3c_registrations (registration_no, name, score)
VALUES ('R006', '王云', 101);
```

```sql
START TRANSACTION;
INSERT INTO c3c_registrations (registration_no, name, score)
VALUES ('R006', '王云', 0), ('R007', '王雨', 100);
SELECT registration_no, score FROM c3c_registrations
WHERE registration_no IN ('R006', 'R007') ORDER BY registration_no;
ROLLBACK;
```

两个边界值 `0.00` 与 `100.00` 都能保存。数据库像报名处值班员，对所有写入路径执行同一条规则。应用程序还能在输入时给出更友好的错误提示。简单且稳定的规则适合数据库把关。唯一索引与约束检查也会增加写入工作，应按规则的必要性来选择。

> ⚠️ **注意** MySQL 8.0.16 开始执行 `CHECK` 约束。遇到旧环境，先试一条非法数据，确认它确实报错。

## 小结

用主键定位行，用唯一约束守住其他会冲突的编号，用非空声明必填，用默认值表达正常缺省，用检查约束拦截非法取值。验收至少试一个有效值和一个应该被拒绝的值。

### 练习 3 · 两列组成身份
