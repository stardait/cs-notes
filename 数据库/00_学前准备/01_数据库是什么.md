# 第 00 章 · 数据库是什么

> 想清楚要存什么、怎么找回来、多人同时改会怎样，再决定要不要用数据库。

## 学习目标

- 用你熟悉的 Python 列表和 JSON 解释数据库解决的具体问题。
- 在 `students` 里辨认表、列、行和主键。
- 看懂第一次建库、建表、录入样本的完整过程。本机已有库时直接查询。

## 准备

启动本机 MySQL，用 HeidiSQL 连到 `127.0.0.1:3306`。具体步骤见[环境说明](../_环境验证/README_环境说明.md)。

## 一、从 Python 变量走到数据库

`students = [{"name": "小明", "score": 92.5}]` 可以在运行中保存数据，进程关闭后，内存里的列表随之结束。写成 JSON 文件能保留下来，存几条配置或交换数据很合适。数据量和需求变化后，下面几件事就要额外设计。

| 场景 | 直接用一个 JSON 文件会遇到什么 | 数据库提供什么 |
|---|---|---|
| 反复查找分数超过 85 的学生 | 朴素做法每次加载再扫描所有记录 | 交给 SQL 执行。合适的索引可能减少读取，速度取决于数据和查询 |
| 两人分别修改不同学生 | 两份旧副本先后覆盖文件，后写的可能覆盖前写的 | 数据库能协调并发，事务的写法和隔离设置仍然重要 |
| 给老记录增设班级字段 | 旧字典可能缺这个键 | 修改表结构时可统一处理。旧值取决于新列定义和默认值 |
| 50 名同班学生共用同一位班主任 | 每人重复存老师信息，换人要改多份 | 班级信息可独立保存，学生只记录所属班级编号 |

数据库适合需要持续查询、管理共同结构、保留数据关系或支持多人操作的场景。关系型数据库组织成表，本教程用 MySQL 学 SQL，再在后续实践里比较 SQLite 的写法。

## 二、拿一张认识的表当地图

| id | name | age | class | score |
|---:|---|---:|---|---:|
| 1 | 小明 | 18 | 一班 | 92.50 |
| 2 | 小红 | 17 | 一班 | 88.00 |

一张表可以理解为同一类记录的登记册。上面每行是一个学生，每列是一类属性。一行含多个字段值，「字段」在入门对话里通常也指列。`id` 是本表主键，要求不重复、无空值，用它才能可靠指到具体一条记录。两个人可以叫同一个名字，他们的主键必须不同。普通表语法上可以没有显式主键，设计业务表时通常应声明一个。

## 三、在自己的库里确认结果

本机已有 `learn.students`。现在只运行这一段。

```sql
USE learn;
SELECT id, name, age, class, score FROM students ORDER BY id;
```

当前样本有 5 行。第一行是小明，最后一行是小强。如果你的表已新增记录，以实际结果为准。读数据的 `SELECT` 会在第 01 章细讲。

### 从空环境第一次初始化

只有在你要初始化一套新环境，且 `learn.students` 确实还不存在时，才使用[首次初始化 SQL](00_首次初始化.sql)。先看脚本开头。HeidiSQL 也可以在左侧右键新建数据库，名字为 `learn`，字符集选 `utf8mb4`，然后在这个库里执行建表与录入步骤。

初次脚本里，`CREATE DATABASE` 负责准备库，`CREATE TABLE` 负责定义学生表，`INSERT` 负责录入 5 条样本。`id INT PRIMARY KEY AUTO_INCREMENT` 比如表示自动分配编号的整数主键。`name VARCHAR(50) NOT NULL` 接收最多 50 字符的姓名，拒绝 SQL 空值。`score DECIMAL(5,2)` 为小数保留两位。第 03、04 章会带你逐条写这些语句。

## 小结

先用表描述你希望记录的事，再为每行找一个稳定身份。有了库、表和主键，就能说清「哪一张表的哪一条记录」。

### 练习 1 · 定位一行

指出 `learn.students` 中，`learn`、`students`、`score`、`id=2` 各是什么。

<summary>展开参考答案</summary>

`learn` 是数据库，`students` 是表，`score` 是列，`id=2` 是定位某一条学生记录的条件。

### 练习 2 · 选一种存法

一个程序只有十条会随部署更新的配置。另一个程序需要五名老师每天查改学生分数。分别选什么？说出理由。

<details>
<summary>展开参考答案</summary>

十条配置放 JSON 文件就可管理。多人反复查询与更新的成绩表更适合数据库，可以统一约束并设计并发写入流程。

</details>

### 练习 3 · 为什么名字不够

如果名单中两人同名，查分时只告诉你名字，能不能确定要查的一行？

<details>
<summary>展开参考答案</summary>
