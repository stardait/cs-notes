# 第 0 章 · 数据库是什么

> 你现在用 Python 存数据，靠的是列表和字典——程序一关就全没了。数据库解决的就是这个问题。
>
> 但数据库不只是「能存下来」，它还解决「怎么快速找到」和「多人同时改不出错」。

---

## 学习目标

读完这篇，你要能回答四个问题：

1. 为什么不能把数据存在 JSON 文件里？
2. 关系型数据库的「表」到底是什么？
3. 主键是什么，为什么必须有？
4. 怎么在 HeidiSQL 里建出第一个数据库？

---

## 一、先看看你现在怎么存数据

### 方式 1：存变量里

```python
students = [
    {"name": "小明", "score": 90},
    {"name": "小红", "score": 85},
]
```

**问题**：程序一关，数据全没。

---

### 方式 2：存 JSON 文件

```python
import json

students = [{"name": "小明", "score": 90}]

with open("students.json", "w", encoding="utf-8") as f:
    json.dump(students, f, ensure_ascii=False)
```

这下能持久化了。但新问题来了——

---

## 二、JSON 文件的四个死穴

### 死穴 1：查一次要读全部

**需求**：找出分数大于 85 的学生。

```python
with open("students.json", encoding="utf-8") as f:
    all_students = json.load(f)          # 先把10万条全读进内存

result = []
for s in all_students:                    # 再一条条判断
    if s["score"] > 85:
        result.append(s)
```

**10 万条数据，每次查询都要读全部、循环一遍。**

数据库里同样的需求：

```sql
SELECT * FROM students WHERE score > 85;
```

**0.01 秒。** 因为它有索引（后面第 7 章讲）。

---

### 死穴 2：两个人同时改会打架

```
你       ：读取 → 改第 3 条 → 写回整个文件
同事     ：读取 → 改第 7 条 → 写回整个文件
                ↓
         后写的覆盖前面的，同事的修改丢了
```

**数据库**：会加锁、会排队、会用事务保证不丢。

---

### 死穴 3：结构一变全崩

```python
# 老数据
{"name": "小明", "score": 90}

# 想加个班级字段
{"name": "小明", "score": 90, "class": "一班"}

# 老数据没有 class，代码读 s["class"] → KeyError
```

**数据库**：用 `ALTER TABLE` 加列，老数据这列自动是 NULL，程序不会崩。

---

### 死穴 4：数据之间有关系就完蛋

一个学生属于一个班，一个班有多个学生：

```json
{
  "name": "小明",
  "class": {"name": "一班", "teacher": "王老师", "room": "301"}
}
```

**现在有 50 个学生都在一班**，班主任换人了怎么办？

```
改 50 个地方 → 漏一个就不一致了
```

**数据库**：班级单独一张表，学生表里存 `class_id`。换老师只改 1 行。

---

## 三、数据库到底解决了什么

| 问题 | JSON 文件 | 数据库 |
|---|---|---|
| 数据不丢 | ✅ 能 | ✅ 能 |
| 快速查询 | ❌ 要读全部 | ✅ 索引，毫秒级 |
| 多人同时改 | ❌ 会覆盖 | ✅ 锁 + 事务 |
| 结构变更 | ❌ 容易崩 | ✅ ALTER TABLE |
| 数据关联 | ❌ 嵌套地狱 | ✅ 外键 + JOIN |

> 💡 **重点**：数据库不是「高级文件」，它是**专门解决「存 + 查 + 并发」这三件事的系统**。

---

## 四、关系型数据库：「表」是什么

关系型数据库用**二维表**组织数据，和 Excel 长得像，但有几条铁律。

### 学生表 `students`

| id | name | age | class | score |
|---|---|---|---|---|
| 1 | 小明 | 18 | 一班 | 92.5 |
| 2 | 小红 | 17 | 一班 | 88.0 |
| 3 | 小刚 | 19 | 二班 | 76.5 |

**四个术语**：

| 术语 | 英文 | 是什么 | 例子 |
|---|---|---|---|
| **表** | Table | 一类东西的集合 | `students` 表 |
| **行** | Row | 一条记录 | 「小明，18，一班，92.5」 |
| **列** | Column | 一个属性 | `name`、`age` |
| **字段** | Field | 列的同义词 | —— |

---

### 和 Excel 的四个区别

| | Excel | 数据库 |
|---|---|---|
| 单元格 | 随便放什么都行 | **每列有固定类型**（整数/文本/日期） |
| 唯一标识 | 没有 | **必须有主键** |
| 数据校验 | 靠人眼看 | **约束强制保证**（非空、唯一） |
| 多人编辑 | 容易冲突 | **事务和锁处理** |

---

## 五、主键：每一行的身份证

**主键（Primary Key）= 能唯一标识一行的那一列。**

```
id | name | age
---+------+-----
 1 | 小明 |  18     ← id=1 唯一确定这一行
 2 | 小红 |  17
 3 | 小刚 |  19
```

### 为什么必须有

**没有主键会怎样**：

```sql
-- 想改小明的分数
UPDATE students SET score = 95 WHERE name = '小明';

-- 问题：如果有两个叫「小明」的，两个都被改了！
```

**有主键**：

```sql
UPDATE students SET score = 95 WHERE id = 1;   -- 精确，只改一个
```

### 主键的两条铁律

1. **不能重复**：两个学生不能有同一个 id
2. **不能为空**：每个学生必须有 id

常见主键：
- 自增整数（`1, 2, 3...`）—— 最简单
- 学号、身份证号 —— 业务上有意义的唯一值
- UUID —— 分布式系统的选择

## 六、动手：在 HeidiSQL 里建第一个库

打开桌面的 **HeidiSQL** 图标。

### 第 1 步：连接 MySQL

```
主机名：127.0.0.1
用户：  root
密码：  Root@2026
端口：  3306
```

点「打开」。

> ⚠️ **注意**：如果连不上，先双击桌面的 `启动MySQL`（不过这个图标我后来删了，现在用命令行启动，见文末）。

---

### 第 2 步：建数据库

在左边「数据库」列表上**右键 → 新建 → 数据库**：

```
数据库名：learn
字符集：  utf8mb4
排序规则：utf8mb4_unicode_ci
```

点「确定」。

然后**双击 `learn`**，让它变粗体（表示当前选中）。

> 💡 **重点**：`utf8mb4` 是必须的，否则中文会变成问号。

---

### 第 3 步：建表

点工具栏 **「新建查询」**（或按 `Ctrl+T`），粘贴：

```sql
CREATE TABLE students (
    id      INT PRIMARY KEY AUTO_INCREMENT,
    name    VARCHAR(50) NOT NULL,
    age     INT,
    class   VARCHAR(20),
    score   DECIMAL(5,2),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

按 **`F9`** 执行。

**每一行的意思**：

| 行 | 含义 |
|---|---|
| `id INT PRIMARY KEY AUTO_INCREMENT` | 整数、主键、自动递增（1,2,3...） |
| `name VARCHAR(50) NOT NULL` | 最多 50 字的文本、不能为空 |
| `age INT` | 整数、可以为空 |
| `class VARCHAR(20)` | 最多 20 字的文本 |
| `score DECIMAL(5,2)` | 小数，总共 5 位、小数点后 2 位（能存 999.99） |
| `created_at DATETIME DEFAULT CURRENT_TIMESTAMP` | 时间，不填就自动用当前时间 |

---

### 第 4 步：插入数据

```sql
INSERT INTO students (name, age, class, score) VALUES
    ('小明', 18, '一班', 92.5),
    ('小红', 17, '一班', 88.0),
    ('小刚', 19, '二班', 76.5),
    ('小美', 18, '二班', 95.0),
    ('小强', 17, '一班', 61.0);
```

按 `F9` 执行。**注意 id 没写**——它会自动变成 1,2,3,4,5。

```sql
SELECT * FROM students;
```

## 七、本章小结

### 四个核心概念

```
数据库（Database）          ← learn
  └── 表（Table）           ← students
        ├── 列（Column）    ← id / name / age / class / score
        └── 行（Row）       ← 一条记录
              └── 主键      ← id（唯一标识）
```

### 数据库 vs JSON 文件

| 场景 | 用什么 |
|---|---|
| 存 10 条配置 | JSON 足够 |
| 存 10 万条要查询的数据 | **数据库** |
| 多人同时改 | **数据库** |
| 数据之间有关联 | **数据库** |

### 三条铁律

1. **每张表必须有主键**（否则无法精确定位一行）
2. **字符集用 utf8mb4**（否则中文乱码）
3. **每列要有明确类型**（数据库靠类型做校验和优化）
