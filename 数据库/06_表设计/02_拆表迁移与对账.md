# 第 06 章 · 拆表迁移与对账

> 拆表要让新表和旧表在每条明细上都能对得起来。

## 学习目标

- 先筛冲突，再按父表到子表的顺序导入。
- 用行数、金额和逐键比较验收一次迁移。

## 准备

安装[本章旧表](00_安装配套表.sql)。这篇会创建 4 张 `c6_work_` 表，首次运行要求这些表名不存在。旧数据 `c6_legacy_sales` 只读。重做前可备份并改名，或跳过创建和写入，直接核对已有成果。
```sql
USE learn;
```

## 一、先找同一编号下互相矛盾的值

```sql
SELECT customer_id FROM c6_legacy_sales
GROUP BY customer_id HAVING COUNT(DISTINCT customer_name, city) > 1;
SELECT sku FROM c6_legacy_sales
GROUP BY sku HAVING COUNT(DISTINCT product_name) > 1;
SELECT order_id FROM c6_legacy_sales
GROUP BY order_id HAVING COUNT(DISTINCT sold_on, customer_id) > 1;
```

三个结果都应为空。这些列在旧表都是非空，因此 `COUNT(DISTINCT a,b)` 能识别不同组合。任意结果不为空就先查权威客户档案、商品表或订单来源。用 `MIN(city)` 随便挑一个城市会把质量问题藏进新表。

## 二、先定约束，再导入数据

普通建表可能隐式提交。先创建四张空表，然后开启单独的写入事务。

```sql
CREATE TABLE c6_work_customers (
    id INT PRIMARY KEY, name VARCHAR(40) NOT NULL, city VARCHAR(30) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE c6_work_products (
    sku VARCHAR(20) PRIMARY KEY, name VARCHAR(40) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE c6_work_orders (
    id INT PRIMARY KEY, sold_on DATE NOT NULL, customer_id INT NOT NULL,
    FOREIGN KEY (customer_id) REFERENCES c6_work_customers(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
CREATE TABLE c6_work_items (
    order_id INT NOT NULL, line_no INT NOT NULL,
    sku VARCHAR(20) NOT NULL, quantity INT NOT NULL CHECK (quantity > 0),
    unit_price DECIMAL(10,2) NOT NULL CHECK (unit_price >= 0),
    PRIMARY KEY (order_id, line_no),
    FOREIGN KEY (order_id) REFERENCES c6_work_orders(id),
    FOREIGN KEY (sku) REFERENCES c6_work_products(sku)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

下面只执行到最后一条插入，还没提交。任一条报错时，在同一连接执行 `ROLLBACK`，再定位失败的键。

```sql
START TRANSACTION;
INSERT INTO c6_work_customers (id, name, city)
SELECT DISTINCT customer_id, customer_name, city FROM c6_legacy_sales;
INSERT INTO c6_work_products (sku, name)
SELECT DISTINCT sku, product_name FROM c6_legacy_sales;
INSERT INTO c6_work_orders (id, sold_on, customer_id)
SELECT DISTINCT order_id, sold_on, customer_id FROM c6_legacy_sales;
INSERT INTO c6_work_items (order_id, line_no, sku, quantity, unit_price)
SELECT order_id, line_no, sku, quantity, unit_price FROM c6_legacy_sales;
```

## 三、看结果再决定提交

在同一连接做核对。新旧明细各 4 行，成交额都是 360.00，新表另有 2 个客户、2 个商品、3 笔订单。

```sql
SELECT COUNT(*) AS line_count, SUM(quantity * unit_price) AS total FROM c6_legacy_sales;
SELECT COUNT(*) AS line_count, SUM(quantity * unit_price) AS total FROM c6_work_items;
SELECT COUNT(*) AS customers FROM c6_work_customers;
SELECT COUNT(*) AS products FROM c6_work_products;
SELECT COUNT(*) AS orders FROM c6_work_orders;

SELECT src.order_id, src.line_no
FROM c6_legacy_sales AS src
LEFT JOIN c6_work_items AS dst ON dst.order_id = src.order_id AND dst.line_no = src.line_no
WHERE dst.order_id IS NULL
   OR dst.sku <> src.sku OR dst.quantity <> src.quantity OR dst.unit_price <> src.unit_price;
```

最后一个结果必须为 0 行。它检查旧行在新侧是否缺失或内容不合。两侧计数相同、键唯一，且旧行都正确迁移，就保证新侧没有多出一条明细。核对后可以另查订单和客户的关联。

保留成果执行 `COMMIT`，发现不符执行 `ROLLBACK`。回滚后空表结构仍在。确认四表为空再重做数据导入。此演练迁移的是一份静态样本，真实并发写入环境还需要确定取数窗口，并演练切换和回退。

## 小结

迁移先验证依赖，按约束顺序导入，再用汇总和逐行对账给出可追踪的结果。

### 练习 2 · 相同总额怎么可能出错

<details>
<summary>展开参考答案</summary>

两行可能各错 5 元且方向相反，汇总不变。按订单号和明细序号连接，逐列比较价格、数量和商品，并检查缺行和新增行。
