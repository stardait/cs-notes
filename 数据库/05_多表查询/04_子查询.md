# 第 05 章 · 子查询

> 外层需要一个门槛、一批编号，还是只想问「有没有」？先决定内层该交出什么。

## 学习目标

- 按预期的输出形状选择标量、IN、EXISTS 或派生表。
- 识别 NOT IN 和 NULL 的陷阱，用相关子查询确定每组的最新行。

## 准备

在 HeidiSQL 选择 `learn`。缺少 `c5_` 表时，先运行[本章配套 SQL](00_安装配套表.sql)。本章使用 5 名客户、7 笔订单、11 条明细、6 种商品，以及一张 3 人的员工表。订单状态为 `paid` 已付款、`pending` 待付款、`cancelled` 已取消。订单 107 是游客已付款订单，`customer_id` 为 `NULL`。
```sql
USE learn;
```

## 一、内层交出一个门槛或一列编号

```sql
SELECT id, name, current_price
FROM c5_products
WHERE current_price > (SELECT AVG(current_price) FROM c5_products)
ORDER BY id;

SELECT id, name FROM c5_customers
WHERE id IN (SELECT customer_id FROM c5_orders WHERE status = 'paid')
ORDER BY id;
```

第一条先比较平均现价约 63.33 元，结果为商品 1、4、6。用 `> (子查询)` 的位置需要一个值。内层若返回多行会报错，返回零行时标量结果是 `NULL`。第二条让内层返回一列候选编号，查得客户 1、2、3。某个编号出现两次只表示它仍在集合里，外层客户不会因此重复。

```sql
SELECT id FROM c5_customers
WHERE id NOT IN (SELECT customer_id FROM c5_orders WHERE status = 'paid')
ORDER BY id;
```

实际为 0 行。游客 107 给内层引入 `NULL`。对客户 4 或 5 来说，比较「不等于这一个未知编号」得不到真；`WHERE` 不保留未知。对客户 1～3，则内层已经出现其编号，明确排除。

## 二、只问有没有时，让内层按外层这一行检查

```sql
SELECT c.id, c.name
FROM c5_customers AS c
WHERE NOT EXISTS (
    SELECT 1 FROM c5_orders AS o
    WHERE o.customer_id = c.id AND o.status = 'paid'
)
ORDER BY c.id;
```

结果是 4、5。`SELECT 1` 可以读成「存在一行就够」，前面的 1 不参与外层计算。内层引用了当前外层行的 `c.id`，所以叫相关子查询。你可以拿客户 4 和 5 逐个代进条件检查。优化器可以改写实际执行计划，手算时按每个候选理解即可。

## 三、查每位客户的最新一单

按时间挑「最新」，时间相同选较大的订单编号。对于每个候选订单，问同一客户是否还有更晚的，或同一时刻但编号更大的。

```sql
SELECT o.customer_id, o.id AS latest_order, o.ordered_at
FROM c5_orders AS o
WHERE o.customer_id IS NOT NULL
  AND NOT EXISTS (
      SELECT 1
      FROM c5_orders AS other
      WHERE other.customer_id = o.customer_id
        AND (other.ordered_at > o.ordered_at
          OR (other.ordered_at = o.ordered_at AND other.id > o.id))
  )
ORDER BY o.customer_id;
```

| customer_id | latest_order | 判断依据 |
|---:|---:|---|
| 1 | 102 | 晚于 101 |
| 2 | 104 | 与 103 同时下单，编号更大 |
| 3 | 105 | 唯一候选 |
| 4 | 106 | 唯一候选 |

这里统计所有状态的订单。若改为「最新已付款订单」，应在外层候选和内层竞争者里都限制 `paid`，否则一笔较新的未付款订单可能把正确候选挤掉。

## 四、把查询的多行结果当作表

```sql
SELECT paid.customer_id, paid.order_count
FROM (
    SELECT customer_id, COUNT(*) AS order_count
    FROM c5_orders
    WHERE customer_id IS NOT NULL AND status = 'paid'
    GROUP BY customer_id
) AS paid
WHERE paid.order_count >= 2
ORDER BY paid.customer_id;
```

内层已经是一位客户一行的临时结果形状。外层通过别名 `paid` 引用它。结果只剩客户 1，订单数 2。这个例子也可直接用 `HAVING`；派生表适合还要把统计结果当成另一层的输入时。

## 小结

先定门槛、集合、存在性或中间结果，再写内层。含空外键时，给 NOT IN 的结论做一个空值反例。

### 练习 2 · 只保留最新的已付款订单

改造本课的最新订单查询，同时确保待付款订单不会参与竞争。

<details>
<summary>展开参考答案</summary>

```sql
SELECT o.customer_id, o.id FROM c5_orders AS o
WHERE o.customer_id IS NOT NULL AND o.status = 'paid'
  AND NOT EXISTS (
      SELECT 1 FROM c5_orders AS other
      WHERE other.customer_id = o.customer_id AND other.status = 'paid'
        AND (other.ordered_at > o.ordered_at
          OR (other.ordered_at = o.ordered_at AND other.id > o.id))
  )
ORDER BY o.customer_id;
```

结果是 (1,102)、(2,103)、(3,105)。
