# 第 05 章 · 为什么要拆表

> 先问一行记录的是什么。把订单、客户和商品当成同一行，会让一笔修改悄悄变成多笔。

## 学习目标

- 从平面订单表中找出重复的客户和商品信息。
- 解释更新、插入和删除异常，画出订单从客户到明细的路径。

## 准备

在 HeidiSQL 选择 `learn`。缺少 `c5_` 表时，先运行[本章配套 SQL](00_安装配套表.sql)。本章使用 5 名客户、7 笔订单、11 条明细、6 种商品，以及一张 3 人的员工表。订单状态为 `paid` 已付款、`pending` 待付款、`cancelled` 已取消。订单 107 是游客已付款订单，`customer_id` 为 `NULL`。
```sql
USE learn;
```

## 一、一份看上去方便的清单

假设每条商品明细都重复存顾客姓名、城市和商品现价。下面是其中三行；先把它理解为导出的表格。

| order_id | line_no | customer_id | 客户名 | 城市 | 商品 | 成交价 |
|---:|---:|---:|---|---|---|---:|
| 101 | 1 | 1 | 林青 | 杭州 | 键盘 | 100.00 |
| 101 | 2 | 1 | 林青 | 杭州 | 鼠标 | 50.00 |
| 102 | 1 | 1 | 林青 | 杭州 | 鼠标 | 55.00 |

- **更新异常**。若林青迁到苏州，档案的城市要改三次。漏掉任意一行，同一客户就会同时属于两个城市。
- **插入异常**。假设一行必须有 `order_id` 和 `line_no`。客户 5 还没有订单，你只能等订单出现，或伪造一笔明细来增加客户。
- **删除异常**。若客户只有一条明细，删除这条明细也抹去了他的档案；要分析取消订单的原因时，清理明细不该删除客户。

以上异常的前提是表格承担了当前档案的职责。如果列的业务含义是「下单时的收货城市」，历史值则应保留。决定是否拆一列之前，先说清它描述的是当前还是当时。

## 二、四张表各认一件事

| 表 | 一行的含义 | 用来定位这一行 |
|---|---|---|
| `c5_customers` | 一个注册客户 | `id` |
| `c5_orders` | 一笔订单 | `id` |
| `c5_order_items` | 一笔订单的一条明细 | `(order_id, line_no)` |
| `c5_products` | 一件商品 | `id` |

单独追踪客户 1、订单 101 和其明细。一次执行这四条语句，比较四个结果格。

```sql
SELECT id, name, city FROM c5_customers WHERE id = 1;
SELECT id, customer_id, status FROM c5_orders WHERE id = 101;
SELECT line_no, product_id, quantity, unit_price
FROM c5_order_items WHERE order_id = 101 ORDER BY line_no;
SELECT id, name, current_price FROM c5_products WHERE id IN (1, 2) ORDER BY id;
```

订单 101 关联客户 1，明细带有商品号 1、2。键盘现在是 120 元，当时这一条成交价是 100 元。计算历史金额需要按明细的 `quantity * unit_price` 求和，101 号订单是 `1×100 + 2×50 = 200` 元。

第 03 章讲过，外键可以约束引用的键存在。`c5_orders.customer_id` 可空来表达游客；只要有值，就要在客户表里找得到。`c5_order_items.order_id` 必填，每条明细都有一笔订单。

## 三、拆开仍能把答案找回来

已经能按四条查询手动拼出结果。下一篇把比对编号这件事交给 `JOIN`。连接会影响结果里的行数，所以写查询前先说你想要「一行一笔订单」还是「一行一条订单明细」。

## 小结

实体的当前信息尽量有清晰的维护位置。某次业务发生时的快照，放在对应事件或明细上。

## 动手练习

### 练习 1 · 没有订单的客户

吴昕还没有下单。现在应当把他的城市存在哪张表？如何确认他已存在？

<details>
<summary>展开参考答案</summary>

```sql
SELECT id, name, city FROM c5_customers WHERE id = 5;
```

返回吴昕、深圳。他的档案可独立存在。

</details>

### 练习 2 · 商品改价

鼠标现价调到 70 元后，订单 101 历史金额应发生什么变化？

<details>
<summary>展开参考答案</summary>

金额仍为 200.00。现价变化写商品表，历史订单计算沿用明细中的成交价和数量。

</details>
