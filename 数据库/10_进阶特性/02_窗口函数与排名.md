# 第 10 章 · 窗口函数与排名

> 按部门求一个平均值会把员工行压掉。窗口函数可以让每一行带着全组的统计一起出现。

## 学习目标

- 解释窗口函数与 GROUP BY 怎样改变结果行数。
- 按业务选择 ROW_NUMBER、RANK、DENSE_RANK，并计算逐行累计额。

## 一、排名之前，先把每件商品算成一行

下面先汇总各商品的已付款销量，再从商品表外连接回来，没卖出的支架记 0。`COALESCE(x, 0)` 在 `x` 为空时取 0。最后同时算三种排名，比较并列后的下一名。

```sql
WITH sold AS (
    SELECT i.product_id, SUM(i.quantity) AS units
    FROM c5_order_items AS i
    JOIN c5_orders AS o ON o.id = i.order_id
    WHERE o.status = 'paid'
    GROUP BY i.product_id
), per_product AS (
    SELECT p.id, p.name, p.category, COALESCE(sold.units, 0) AS units
    FROM c5_products AS p
    LEFT JOIN sold ON sold.product_id = p.id
)
SELECT id, name, category, units,
       ROW_NUMBER() OVER (PARTITION BY category ORDER BY units DESC, id) AS seq,
       RANK() OVER (PARTITION BY category ORDER BY units DESC) AS place,
       DENSE_RANK() OVER (PARTITION BY category ORDER BY units DESC) AS dense_place
FROM per_product
ORDER BY category, seq;
```

| 类别 | 商品 | 销量 | seq | place | dense_place |
|---|---|---:|---:|---:|---:|
| 配件 | 鼠标 | 3 | 1 | 1 | 1 |
| 配件 | 键盘 | 2 | 2 | 2 | 2 |
| 配件 | USB线 | 2 | 3 | 2 | 2 |
| 配件 | 支架 | 0 | 4 | 4 | 3 |
| 食品 | 咖啡豆 | 3 | 1 | 1 | 1 |
| 食品 | 茶包 | 3 | 2 | 1 | 1 |

表内按类别展示，SQL 的类别先后取决于排序规则。`PARTITION BY` 划开计算范围，`OVER` 内的 `ORDER BY` 定义怎样排名。最终展示顺序仍靠最外层 `ORDER BY`。`ROW_NUMBER` 产生唯一序号，所以加 ID 打破并列。`RANK` 保留并列并跳号，`DENSE_RANK` 保留并列但不跳号。在并列规则里贸然加 ID，会把业务上的同销量变成不同名次。

想要「每组只取两条」用 `ROW_NUMBER`，再由外层筛 `seq <= 2`。想「包含并列第二」可以筛 `RANK <= 2`。当前查询层要先完成窗口计算，`WHERE` 不能直接用这一层的 `seq`。

## 二、累计金额的窗口要写清楚

```sql
WITH paid_totals AS (
    SELECT o.id AS order_id, o.ordered_at,
           SUM(i.quantity * i.unit_price) AS total
    FROM c5_orders AS o
    JOIN c5_order_items AS i ON i.order_id = o.id
    WHERE o.status = 'paid'
    GROUP BY o.id, o.ordered_at
)
SELECT order_id, total,
       SUM(total) OVER (
           ORDER BY ordered_at, order_id
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_total
FROM paid_totals
ORDER BY ordered_at, order_id;
```

| order_id | total | running_total |
|---:|---:|---:|
| 101 | 200.00 | 200.00 |
| 102 | 95.00 | 295.00 |
| 103 | 120.00 | 415.00 |
| 105 | 210.00 | 625.00 |
| 107 | 25.00 | 650.00 |

这里要求逐笔累加。`ROWS` 把范围明确为由第一行至当前行的位置区间。102 与 103 下单时间相同，用订单号决定先后，否则两步的中间总额没有确定顺序。若要每个客户单独累计，在明细汇总后保留客户号，增加 `PARTITION BY customer_id`，并先确认如何对待游客。

## 小结

先把输入行做成正确粒度，再定分区、并列、窗口范围与最终排序。排序字段不同会改变业务结果。

## 动手练习

### 练习 1 · 每个类别成交额前 3

只纳入有已付款订单的商品。每类最多三种，金额并列时小编号优先。

<details>
<summary>展开参考答案</summary>

```sql
WITH per_product AS (
    SELECT p.id, p.category, p.name, SUM(i.quantity * i.unit_price) AS revenue
    FROM c5_order_items AS i
    JOIN c5_orders AS o ON o.id = i.order_id
    JOIN c5_products AS p ON p.id = i.product_id
    WHERE o.status = 'paid'
    GROUP BY p.id, p.category, p.name
), ranked AS (
    SELECT id, category, name, revenue,
           ROW_NUMBER() OVER (PARTITION BY category ORDER BY revenue DESC, id) AS seq
    FROM per_product
)
SELECT category, name, revenue FROM ranked WHERE seq <= 3 ORDER BY category, seq;
```

配件为键盘 205.00、鼠标 155.00、USB线 40.00；食品为咖啡豆 185.00、茶包 65.00。
