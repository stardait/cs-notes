# Shell 学习计划｜Git Bash 入门（4 天）

沿用你在 Windows 上的 Git Bash 和现有的学习目录。主线共 7 课。每天预留约 3 小时读讲义、做独立练习和复盘，有余力再拓展。原先预留的 5 小时可以当上限，做完当天自测就可以收工。

四天后，你应该能在陌生目录里找到文件，从日志里筛出需要的信息，并写一个接收文件路径、能正确报告失败的 Bash 脚本。

## 为什么学 Shell

终端是你打命令、看输出的界面。Shell 负责解释命令和组织程序运行，Bash 是其中一种。Git Bash 是你在 Windows 上练习 Bash 的环境。

- **Python**：进入项目、运行程序和测试时，能判断程序是从哪个目录启动的。遇到「文件不存在」，能检查相对路径究竟指向哪里。复杂的解析和业务逻辑继续交给 Python。
- **数据库**：SQL 在数据库里查表和聚合。Shell 在外面启动 MySQL 客户端、传入 SQL 文件、保存输出，并检查操作是否成功。以后做导出和恢复时，会用到同一套输入、输出和退出状态。
- **Git 与项目开发**：每次操作前先确认当前项目，读懂工具报错，必要时把测试或构建结果写到文件。这些操作也会出现在持续集成（CI）里。
- **操作系统与 Linux**：从执行命令出发，逐步理解工作目录、进程、标准输入输出和退出状态。学到权限和服务时，再去 Linux 或 WSL 实地验证。

## 每节怎么教

每节先定一个可以验证的结果，例如「从日志里找出两条错误，并说出怎么确认」。我先演示一个最小例子，讲清它从哪读、对什么操作、结果去哪。接着你先预测输出，自己敲一遍，再换一个路径或条件独立重做。

卡住时，先保留原命令和报错，核对当前目录、路径、引号和选项。我先给一条定位提示，等你试过，再拆开讲解。每日笔记写在 `notes/`，只记一个学会的问题、一个踩过的坑、一个隔天能重做的题。第一轮重点练 Bash 特有的路径、引号、数据流和退出状态，你已有的 Python 循环、条件和函数概念可以直接迁移。

后续课程的命令默认从 `shell/` 目录开始。新开 Git Bash 时，先用第一节的绝对路径进入这里。课程讲义在 `lesson/`，练习文件放 `practice/`，脚本放 `scripts/`，可选的数据库导出放 `backups/`。搜索时可以读取现有学习资料。

## 第 1 天｜完成路径定位和文件操作

1. [当前目录与相对路径](./lesson/01_当前目录与相对路径.md) · 约 25 分钟。用 `pwd`、`cd`、`ls` 定位，再修一次文件路径。
2. [创建、复制和移动文件](./lesson/02_创建复制和移动文件.md) · 约 45 分钟。在 `practice/day1/` 创建文件，把含空格的副本移动并改名。

**当天自测**

能在同级目录之间往返，能指出复制和移动命令的来源与目标，并核对结果。

## 第 2 天｜找到需要的内容并保存结果

3. [查找文件与搜索内容](./lesson/03_查找文件与搜索内容.md) · 约 45 分钟。创建后续共用的 `practice/day2/session.log`，再去真实的数据库笔记里找 `JOIN`。
4. [管道与重定向](./lesson/04_管道与重定向.md) · 约 50 分钟。用同一份日志做筛选、计数和保存，观察正常输出与报错各去哪里。

**当天自测**

能解释 `find` 和 `grep` 分别解决什么问题，能把警告行存成文件并核对数量。

## 第 3 天｜把手工命令变成脚本

5. [编写脚本与传参](./lesson/05_编写脚本与传参.md) · 约 50 分钟。写 `show_log.sh`，从传入的路径读取日志开头。
6. [退出状态与错误处理](./lesson/06_退出状态与错误处理.md) · 约 60 分钟。写 `list_errors.sh`，区分找到匹配、无匹配和读取失败。

**当天自测**

脚本能读取含空格的路径，能在出错时把信息送到标准错误，并通过退出状态让调用方识别失败。

## 第 4 天｜完成并验收小项目

7. [日志摘要项目](./lesson/07_日志摘要项目.md) · 约 90～120 分钟。完成 `log_summary.sh`，验证正常日志、零匹配、带空格的路径、缺失文件和没有参数这五种情况。

**当天自测**

能独立跑完五个验收用例，能把摘要存成文件并确认源日志仍可读取。

## 数据库进阶选练

等日志项目通过，再用 `mysqldump` 导出专门创建的练习库。使用 `-p` 让客户端提示输入密码，先手动查看报错和退出状态。把结果导入另建的空练习库，核对表结构、行数和代表性数据。能重复手动备份并验证恢复后，再考虑脚本化和定时运行。

## 四天后怎么接着用

把 Shell 带回日常学习。下次运行 Python 项目时先确认工作目录，查数据库笔记时先试一次 `grep`，需要重复出报告时再考虑写脚本。进入 Linux 或操作系统章节后，用同样的小练习观察文件权限、进程和服务。

需要第二种讲法时，可以读 MIT 课程的导航部分，练完第 2 天再回来看管道和重定向。[MIT Missing Semester · Shell 入门](https://missing.csail.mit.edu/2026/course-shell/)
