# 第 6 课｜退出状态与错误处理

**用时约 60 分钟。** 上一课在用法错误时写了 `exit 2`。这一课反过来思考「我作为调用方，怎样知道刚刚执行的是成功、查无结果，还是失败？」从 `shell/` 开始，用第 3 课的 `session.log` 做实验。

## 1. 屏幕上的数字和程序返回的数字各说一件事

第 4 课用 `grep | wc -l` 数匹配行。现在用 `grep -c` 直接返回匹配**行数**，然后观察第二个数字。Bash 把最近完成的命令的退出状态放在 `$?` 里。每条 `printf` 都紧挨它要检查的那条命令。

```bash
grep -c -- '^ERROR ' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

grep -c -- '^DEBUG ' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

grep -c -- '^ERROR ' 'practice/day2/missing.log'
printf '状态：%s\n' "$?"
```

第一组的 `2` 是两条匹配，状态 `0` 表示找到了。第二组的 `0` 是找到零条，状态 `1` 表示查过但无匹配。第三组会报路径不存在，状态一般是 `2`。对 `grep`，大于 `1` 表示出错。

如果先跑一次 `ls`，`$?` 就会变成 `ls` 的状态。在脚本里要稍后判断，可以在命令下面立即写 `status=$?`，把当时的值存进普通变量。这和上一课的 `log=$1` 用的是同一种赋值。

## 2. `if` 为什么可以直接跟一条命令？

上一课用 `[[ ... ]]` 做判断。那个条件也会产生退出状态，成立时为 `0`。Bash 的 `if` 就是根据紧跟着的命令的状态选分支，所以也能直接检查 `grep`。把 `-c` 换成 `-n`，它会打印匹配行和行号，退出状态的含义照旧。

在终端先跑这个小实验。跑完把 `^ERROR ` 换成 `^DEBUG ` 再试。

```bash
if grep -n -- '^ERROR ' 'practice/day2/session.log'
then
    printf '找到了匹配\n'
else
    status=$?
    printf 'grep 的状态是 %s\n' "$status"
fi
```

使用 `ERROR` 时先显示两条匹配，再执行 `then`。换成 `DEBUG` 时进入 `else`，显示状态 `1`。`else` 的第一行就保存状态，因为接下来的任何打印也会产生自己的状态。`then` 换到下一行是为了好读，你在别处看到的 `if 命令; then` 用分号标记了同一处命令边界。

## 3. 先决定脚本把什么当成成功

对人来说，「已经查完，零条」也是有用的结果。脚本可以这样处理 `grep` 的三种状态。

- `0` 时，`grep -n` 已经把匹配行送到标准输出，脚本成功结束。
- `1` 时，文件查过了，打印「没有错误行」，正常结束。
- 大于 `1` 时，查询失败。保留 `grep` 的诊断，让脚本把失败状态传回调用者。

这里需要比较保存好的 `status`。`[[ "$status" -eq 1 ]]` 中的 `-eq` 问两个数字是否相等。第 5 课的 `-ne` 问是否不相等。`exit "$status"` 和上一课的 `exit 2` 用法相同，只是数值这次来自变量。

在查内容之前，还有两个检查。`$#` 确保输入是一个路径。`[[ -f "$log" ]]` 检查它是否指向普通文件，前面加 `!` 就反过来检查。可以把 `practice/day2` 目录和 `practice/day2/session.log` 分别代进去，先预测结果。下面参考实现还照顾了名为 `-` 的文件。单独的 `-` 对 `grep` 表示从标准输入读取，`./-` 则明确指向当前目录中的文件。

## 4. 把判断拼成脚本

用 `mkdir -p 'practice/review'` 准备复盘目录。在编辑器里新建 `practice/review/list_errors.sh`，保存为 UTF-8、LF。先按「检查参数 → 检查路径 → 搜索 → 处理状态」写出自己的版本，再展开对照。参考实现里的 `exit` 是脚本流程的一部分。

<details>
<summary>完整脚本，用来对照你的版本</summary>

```bash
#!/usr/bin/env bash

if [[ $# -ne 1 ]]
then
    printf '用法：bash %s 日志路径\n' "$0" >&2
    exit 2
fi

log=$1
if [[ "$log" == '-' ]]
then
    log='./-'
fi

if [[ ! -f "$log" ]]
then
    printf '找不到普通文件：%s\n' "$log" >&2
    exit 2
fi

if grep -n -- '^ERROR ' "$log"
then
    exit 0
else
    status=$?
fi

if [[ "$status" -eq 1 ]]
then
    printf '没有错误行\n'
else
    exit "$status"
fi
```

`==` 在 `[[ ... ]]` 中用于这里的文字比较，问路径是否正好等于那个单独的横杠。`-eq` 比的是数字。打印「没有错误行」后代码走到末尾，最后一条 `printf` 的成功状态也就是脚本的退出状态。

</details>

**回头看第 4 课。** 如果源路径错了，管道中的 `grep` 会报错，而 `wc -l` 仍可能把空输入数成 `0`。在 Git Bash 的默认设置下，管道的退出状态取最后一段。第 7 课会直接用 `grep -c`，这样计数和它的执行状态都来自同一条命令。

## 5. 验证每条分支

```bash
printf '%s\n' 'INFO start' 'INFO complete' > 'practice/day2/only-info.log'
bash -n 'practice/review/list_errors.sh'

bash 'practice/review/list_errors.sh' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

bash 'practice/review/list_errors.sh' 'practice/day2/only-info.log'
printf '状态：%s\n' "$?"

bash 'practice/review/list_errors.sh' 'practice/day2/missing.log'
printf '状态：%s\n' "$?"
```

预期依次是两条带行号的错误和状态 `0`、「没有错误行」和状态 `0`、报错和状态 `2`。第二种结果很重要。对 `grep` 来说没有匹配是状态 `1`，对你的脚本来说「已成功检查，结果为空」是正常完成。

**过关标准**

能说明「无匹配」和「读取失败」对调用方分别意味着什么。能在调用之后立即检查状态，并知道自己的脚本在哪个分支给出了结果。
