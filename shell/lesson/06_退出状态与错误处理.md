# 第 6 课｜退出状态与错误处理

**用时约 60 分钟。** 从 `shell/` 开始。你会区分找到匹配、没有匹配和命令执行失败这三种结果。用第 3 课的 `session.log` 练习，最后完成一个列出错误行的脚本。

## 1. 输出给人看，退出状态给调用方判断

每条 `grep` 后紧接着运行 `printf`，查看刚才的退出状态。

```bash
grep -c -- '^ERROR ' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

grep -c -- '^DEBUG ' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

grep -c -- '^ERROR ' 'practice/day2/missing.log'
printf '状态：%s\n' "$?"
```

- 第一次输出 `2`，状态是 `0`，表示找到匹配。
- 第二次输出 `0`，状态是 `1`，表示没有匹配。
- 第三次会报找不到文件，在 Git Bash 里通常返回 `2`。`grep` 用大于 `1` 的状态表示发生错误。

`$?` 是刚结束的命令或管道的状态。如果中间先运行了 `ls`，再查询就会得到 `ls` 的状态。要留着稍后判断，可以用 `status=$?` 立即保存。

## 2. 看看管道为什么可能显示一个误导的 0

```bash
(
    set +o pipefail
    grep -- '^ERROR ' 'practice/day2/missing.log' | wc -l
    printf '管道状态：%s\n' "$?"
)
```

`grep` 会报文件不存在，`wc -l` 仍能把空输入数成 `0`。这里明确关闭了 `pipefail`，管道状态取最后一段 `wc` 的状态，因此也是 `0`。括号里的设置只在这组命令中生效。这就是第 7 课会直接用 `grep -c` 并检查它的状态的原因。

## 3. 把三种结果写进脚本

在编辑器里创建 `scripts/list_errors.sh`，保存为 UTF-8、LF。它接收一个日志路径，输出错误行及其行号。

```bash
#!/usr/bin/env bash

if [[ $# -ne 1 ]]; then
    printf '用法：bash %s 日志路径\n' "$0" >&2
    exit 2
fi

log=$1
if [[ "$log" == '-' ]]; then
    log='./-'
fi

if [[ ! -f "$log" ]]; then
    printf '找不到普通文件：%s\n' "$log" >&2
    exit 2
fi

if grep -n -- '^ERROR ' "$log"; then
    exit 0
else
    status=$?
fi

if [[ $status -eq 1 ]]; then
    printf '没有错误行\n'
else
    exit "$status"
fi
```

先检查参数个数。`grep` 把单独的 `-` 当作标准输入，所以遇到这个文件名时，先写成 `./-`。最后用 `-f` 检查路径是否指向普通文件。

`if grep ...` 直接判断该命令的状态。若走到 `else`，第一句先记下原状态。没有匹配时，脚本会正常报告「没有错误行」。如果 `grep` 读文件失败等，它的原始报错仍会出现在标准错误，脚本也会传回非零状态。

## 4. 验证每条分支

```bash
printf '%s\n' 'INFO start' 'INFO complete' > 'practice/day2/only-info.log'
bash -n 'scripts/list_errors.sh'

bash 'scripts/list_errors.sh' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

bash 'scripts/list_errors.sh' 'practice/day2/only-info.log'
printf '状态：%s\n' "$?"

bash 'scripts/list_errors.sh' 'practice/day2/missing.log'
printf '状态：%s\n' "$?"
```

预期依次是两条带行号的错误和状态 `0`、「没有错误行」和状态 `0`、报错和状态 `2`。第二种结果很重要。对 `grep` 来说没有匹配是状态 `1`，对你的脚本来说「已成功检查，结果为空」是正常完成。

**过关标准**

能说明「无匹配」和「读取失败」对调用方分别意味着什么。能在调用之后立即检查状态，并知道自己的脚本在哪个分支给出了结果。
