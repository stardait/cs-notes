# 第 7 课｜日志摘要项目

**用时约 90～120 分钟。** 你已经能数错误行。现在把「数一次」变成一份可被别的命令调用的结果。从 `shell/` 开始，用 `mkdir -p 'practice/review'` 准备复盘目录，逐步写出 `practice/review/log_summary.sh`。你原先做好的 `scripts/log_summary.sh` 可以用来对照。

## 1. 先想调用者究竟需要什么

别人给你一个日志路径，希望得到以 `ERROR ` 开头的行数。屏幕上看到一个数字只是第一步。这个数字之后还可能被保存到文件，或交给下一条命令，因此调用者也要知道这次检查是否成功。

- 检查成功时，标准输出只有整数。没有错误行时，输出 `0` 并正常结束。
- 遇到错误路径或读取失败时，把诊断留在标准错误，并以非零状态结束。
- 脚本自己负责读输入。想把结果存在哪儿，由调用者决定。

回想第 6 课。文件不存在时，`grep | wc -l` 也可能得到 `0`。这里需要保留「结果数字」和「查询状态」这两份信息。

## 2. 先拿到结果，等确认成功后再发布

第 6 课已经用过 `grep -c`。先跑这条，确认它能直接得到主样本的错误数。

```bash
grep -c -- '^ERROR ' 'practice/day2/session.log'
```

预期是 `2`。我们还要决定是否把这个数字交给下游，所以先存下来。第 5 课通过 `log=$1` 把参数存进变量。现在变量的值需要**运行一条命令**才能得到。`$(命令)` 就是这一步，它运行括号里的命令，把标准输出接成一段文字，并去掉末尾的换行符。

```bash
count=$(grep -c -- '^ERROR ' 'practice/day2/session.log')
status=$?
printf '匹配数=%s，grep 状态=%s\n' "$count" "$status"
```

`$count` 是取已有变量的值。`$(...)` 则会先运行命令，再把结果放到这个位置。这里捕获的是标准输出，因此诊断仍走标准错误。第一行只有赋值和一次命令替换，它的退出状态来自这次 `grep`。所以把 `status=$?` 紧挨在下面。把路径换成 `only-info.log`，你应该得到匹配数 `0`、状态 `1`。只看其中一个数字，都无法完整地描述这次运行。

## 3. 用前两课的积木推到完整脚本

先写下你自己的处理顺序，再写 Bash。

1. 沿用第 5 课的 `$#` 和 `$1`，让脚本接收一个路径。
2. 沿用第 6 课的 `-f`，拒绝目录或不存在的路径。
3. 用上面两行把计数和状态保存下来。第 6 课学过 `-eq` 比较相等，这里用 `-gt` 问「数字是否大于 `1`」。大于 `1` 说明查询失败，沿用 `exit "$status"` 把失败交回调用者。
4. 其余状态来自一次有效的查询，用 `printf '%s\n' "$count"` 输出数字。这样状态 `1` 的零条匹配也能成为一个成功的摘要结果。

写完后先挑一个场景，用手指沿着脚本逐行走一遍。选择只有 INFO 的日志时，`count` 会是什么，哪个分支会走，屏幕最终会看到什么？

<details>
<summary>参考实现，用来对照你的推导</summary>

将脚本保存为 UTF-8、LF。以下代码放在文件里，`exit` 用来结束这次脚本调用。

```bash
#!/usr/bin/env bash

if [[ $# -ne 1 ]]
then
    printf '用法：bash %s 日志路径\n' "$0" >&2
    exit 2
fi

log=$1
if [[ "$log" == '-' ]]
then
    log='./-'
fi

if [[ ! -f "$log" ]]
then
    printf '找不到普通文件：%s\n' "$log" >&2
    exit 2
fi

count=$(grep -c -- '^ERROR ' "$log")
status=$?
if [[ "$status" -gt 1 ]]
then
    exit "$status"
fi

printf '%s\n' "$count"
```

用只有 INFO 的样本时，`count` 是 `0`、`status` 是 `1`，所以跳过失败分支。最后的 `printf` 正常输出 `0`，Bash 以这条命令的状态结束脚本。`grep` 如果真的失败，原始诊断会经标准错误显示，脚本也会在打印摘要之前退出。

</details>

## 4. 做五个验收用例

如果缺少测试文件，可以回到 [第 3 课](03_查找文件与搜索内容.md) 创建主样本、[第 5 课](05_编写脚本与传参.md) 复制带空格的样本、[第 6 课](06_退出状态与错误处理.md) 创建只有 INFO 的日志。运行以下命令，逐个把输出和状态与预期对上。

```bash
bash -n 'practice/review/log_summary.sh'

bash 'practice/review/log_summary.sh' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

bash 'practice/review/log_summary.sh' 'practice/day2/only-info.log'
printf '状态：%s\n' "$?"

bash 'practice/review/log_summary.sh' 'practice/day2/session copy.log'
printf '状态：%s\n' "$?"

bash 'practice/review/log_summary.sh' 'practice/day2/missing.log'
printf '状态：%s\n' "$?"

bash 'practice/review/log_summary.sh'
printf '状态：%s\n' "$?"
```

1. 主样本有两条以 `ERROR ` 开头的行，应输出 `2`，返回 `0`。
2. 只有 INFO 的样本应输出 `0`，返回 `0`。
3. 带空格的副本应输出 `2`，返回 `0`。
4. 缺失文件应给出路径错误，返回非零状态。
5. 没传参数应给出用法，返回非零状态。

## 5. 检查输出能否交给下一个工具

```bash
bash 'practice/review/log_summary.sh' 'practice/day2/session.log' > 'practice/review/summary.txt'
printf '状态：%s\n' "$?"
cat 'practice/review/summary.txt'
wc -l < 'practice/day2/session.log'
```

检查状态为 `0`，摘要只有一行 `2`，源日志仍有五行。输出目录里有文件，只说明重定向打开了它。程序是否正常完成要看退出状态。

再测一次失败，把两个输出通道分开。

```bash
bash 'practice/review/log_summary.sh' 'practice/day2/missing.log' \
    > 'practice/review/failed.out' 2> 'practice/review/failed.err'
printf '状态：%s\n' "$?"
wc -c < 'practice/review/failed.out'
cat 'practice/review/failed.err'
```

应得到非零状态，`failed.out` 的字节数为 `0`，`failed.err` 里能看到错误说明。脚本的结果因此可以作为其他命令的输入，诊断信息则留给人查看。
