# 第 7 课｜日志摘要项目

**用时约 90～120 分钟。** 从 `shell/` 开始。今天的交付是 `scripts/log_summary.sh`，一个读文本日志、输出错误行数的小工具。样本使用前几课生成的 `practice/day2/session.log`。

## 1. 先规定输入和输出

- 输入一个日志文件路径。使用带空格的相对路径时，在调用处加引号。
- 只数以 `ERROR `（末尾有空格）开头的行。标准输出只放一个整数和换行。
- 成功检查的状态是 `0`，即使没有错误行。参数或文件有问题时，把说明写到标准错误，并返回非零状态。

脚本写好后，第一条命令应在屏幕显示 `2`。第二条会把相同的数字存进 `summary.txt`。

```bash
bash 'scripts/log_summary.sh' 'practice/day2/session.log'
bash 'scripts/log_summary.sh' 'practice/day2/session.log' > 'practice/day2/summary.txt'
```

## 2. 先在终端拼出核心，再写脚本

```bash
count=$(grep -c -- '^ERROR ' 'practice/day2/session.log')
status=$?
printf '匹配数=%s，grep 状态=%s\n' "$count" "$status"
```

`$(...)` 把命令的标准输出收进变量。在这里，这条变量赋值的退出状态来自 `grep`，所以紧接着用 `status=$?` 保存。把样本换成只有 `INFO` 的日志再试一次，观察为什么 `count` 和 `status` 需要分别判断。

自己写时可以分三步。先让脚本能对正常样本输出 `2`，再加参数和文件检查，最后处理 `grep` 的退出状态。用编辑器把脚本保存为 UTF-8、LF。

<details>
<summary>参考实现</summary>

```bash
#!/usr/bin/env bash

if [[ $# -ne 1 ]]; then
    printf '用法：bash %s 日志路径\n' "$0" >&2
    exit 2
fi

log=$1
if [[ "$log" == '-' ]]; then
    log='./-'
fi

if [[ ! -f "$log" ]]; then
    printf '找不到普通文件：%s\n' "$log" >&2
    exit 2
fi

count=$(grep -c -- '^ERROR ' "$log")
status=$?
if [[ $status -gt 1 ]]; then
    exit "$status"
fi

printf '%s\n' "$count"
```

`grep -c` 成功匹配时输出数量并返回 `0`。零匹配时它输出 `0` 并返回 `1`，所以两种情况都可以打印 `count`。状态大于 `1` 时，保留 `grep` 的原始报错和失败状态。最后一条 `printf` 成功时，脚本也以状态 `0` 结束。

</details>

## 3. 做五个验收用例

如果缺少测试文件，可以回到 [第 3 课](03_查找文件与搜索内容.md) 创建主样本、[第 5 课](05_编写脚本与传参.md) 复制带空格的样本、[第 6 课](06_退出状态与错误处理.md) 创建只有 INFO 的日志。运行以下命令，逐个把输出和状态与预期对上。

```bash
bash -n 'scripts/log_summary.sh'

bash 'scripts/log_summary.sh' 'practice/day2/session.log'
printf '状态：%s\n' "$?"

bash 'scripts/log_summary.sh' 'practice/day2/only-info.log'
printf '状态：%s\n' "$?"

bash 'scripts/log_summary.sh' 'practice/day2/session copy.log'
printf '状态：%s\n' "$?"

bash 'scripts/log_summary.sh' 'practice/day2/missing.log'
printf '状态：%s\n' "$?"

bash 'scripts/log_summary.sh'
printf '状态：%s\n' "$?"
```

1. 主样本有两条以 `ERROR ` 开头的行，应输出 `2`，返回 `0`。
2. 只有 INFO 的样本应输出 `0`，返回 `0`。
3. 带空格的副本应输出 `2`，返回 `0`。
4. 缺失文件应给出路径错误，返回非零状态。
5. 没传参数应给出用法，返回非零状态。

## 4. 检查输出能否交给下一个工具

```bash
bash 'scripts/log_summary.sh' 'practice/day2/session.log' > 'practice/day2/summary.txt'
printf '状态：%s\n' "$?"
cat 'practice/day2/summary.txt'
wc -l < 'practice/day2/session.log'
```

检查状态为 `0`，摘要只有一行 `2`，源日志仍有五行。输出目录里有文件，只说明重定向打开了它。程序是否正常完成要看退出状态。

再测一次失败，把两个输出通道分开。

```bash
bash 'scripts/log_summary.sh' 'practice/day2/missing.log' \
    > 'practice/day2/failed.out' 2> 'practice/day2/failed.err'
printf '状态：%s\n' "$?"
wc -c < 'practice/day2/failed.out'
cat 'practice/day2/failed.err'
```

应得到非零状态，`failed.out` 的字节数为 `0`，`failed.err` 里能看到错误说明。脚本的结果因此可以作为其他命令的输入，诊断信息则留给人查看。

## 5. 独立迁移

另外建一个练习日志，其中一行以 `WARN ` 开头，另一行的正文里也包含词语 `WARN`。先预测结果，再用第 3、4 课的命令核对。如果还有余力，复制参考脚本的思路写一个统计警告的版本，保留对零匹配与失败的处理。

<details>
<summary>检查思路</summary>

核心匹配用 `^WARN `，先用 `grep -n` 看匹配到哪一行，再用 `grep -c` 核对数量。只有以 `WARN ` 开头的那一条应该被计数。换成只有 INFO 的日志、再换成不存在的路径，检查新脚本是否依然能区分两种情况。

</details>

**结课标准**

能独立说明输入路径怎么传，计数怎么得来，输出和错误各去哪里，以及为什么零匹配对摘要工具来说代表成功。
