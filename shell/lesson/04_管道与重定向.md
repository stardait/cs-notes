# 第 4 课｜管道与重定向

**用时约 50 分钟。** 从 `shell/` 开始，使用第 3 课生成的 `practice/day2/session.log`。如果文件还没准备好，先做 [第 3 课的准备步骤](03_查找文件与搜索内容.md)。

## 1. 一条命令负责筛选，另一条负责计数

你已经会用 `grep` 筛出错误原文。现在想把数行这件事也交给电脑。试试 `wc -l`，它会统计换行符，`-l` 选的是行数这一项。

```bash
grep -- '^ERROR ' 'practice/day2/session.log'
wc -l 'practice/day2/session.log'
```

第一条显示两条错误。第二条数的是整个文件，所以显示 `5` 和文件名。我们需要的是用第二条的计数能力处理第一条已经筛过的内容。把这份中间结果交过去，就得到下面这条命令。

```bash
grep -- '^ERROR ' 'practice/day2/session.log' | wc -l
```

`grep` 发出的正常结果叫**标准输出**。`|` 让 Bash 把这份输出送给 `wc` 的**标准输入**。右边已经从管道收到数据，所以文件路径留在左边。输出应是 `2`。这两条日志都带换行，因此换行符个数也是记录数。

```text
session.log → grep 筛选 → 两条错误文本 → wc -l 计数 → 屏幕显示 2
```

可以先遮住最右边的命令，口头说出管道中间流过什么。再想想如果改成 `grep -n`，中间文本会多出什么，最终数字会变吗？

## 2. 让文件接收原本会显示在屏幕上的文字

如果你要发给别人的是两行原文，只让 `grep` 产生结果，再由 Bash 把正常输出写进文件。`>` 右边是接收输出的路径。

```bash
grep -- '^ERROR ' 'practice/day2/session.log' > 'practice/day2/error-report.txt'
cat 'practice/day2/error-report.txt'
```

现在 `grep` 的结果进了 `error-report.txt`。看见什么内容取决于 `>` 左边是谁。如果左边是完整的 `grep ... | wc -l`，把 `>` 放在 `wc -l` 后面，存下来的就是数字。

接着要加一句检查备注，保留原文。这时用 `>>` 追加。

```bash
printf '%s\n' '已检查错误记录' >> 'practice/day2/error-report.txt'
cat 'practice/day2/error-report.txt'
```

你应看到原来的两行和第三行备注。`>` 打开目标时会清空旧内容，`>>` 会从末尾接着写。每次写之前先核对右边的路径，给源日志和报告使用不同的名字。

## 3. 让文件作为输入，把报错送到单独的地方

上一节是输出走向文件。如果要从文件往命令送数据，用 `<`。在 `wc -l < 路径` 中，Bash 打开文件，`wc` 从标准输入读到内容，和上面从管道读数据的入口相同。

```bash
wc -l < 'practice/day2/session.log'
```

应只显示 `5`。像第 1 节那样直接给 `wc` 一个文件名时，它自己打开文件，输出通常还会带文件名。两种写法都能数行，区别来自由谁打开文件、数据走哪个入口。

再想一个问题。如果路径不存在，错误信息要发到哪？命令通常把诊断信息交给**标准错误**。Bash 把标准输出编号为 `1`，标准错误编号为 `2`。所以 `> 文件` 默认接走 `1`，`2> 文件` 指定接走 `2`。数字 `2` 要紧挨着 `>`，Bash 才把它读成通道编号。

```bash
ls 'practice/day2/does-not-exist' 2> 'practice/day2/stderr.txt'
cat 'practice/day2/stderr.txt'
```

第一条会失败，诊断被写入 `stderr.txt`，随后的 `cat` 才把它显示到屏幕。普通的 `|` 传递的是标准输出。这两个输出通道可以同时存在，后面写脚本时就能让数字和报错各走自己的通道。

## 4. 独立练习

从同一份日志筛出所有 `WARN ` 开头的行，先在终端计数，再把原文存入 `practice/day2/warnings.txt`。最后从文件读入并验证行数。想一想，计数命令和保存命令分别保存了什么。

<details>
<summary>参考答案与检查</summary>

```bash
grep -- '^WARN ' 'practice/day2/session.log' | wc -l
grep -- '^WARN ' 'practice/day2/session.log' > 'practice/day2/warnings.txt'
wc -l < 'practice/day2/warnings.txt'
cat 'practice/day2/warnings.txt'
```

两次计数都应为 `1`，`warnings.txt` 里应只有 `WARN slow query`。管道把匹配行交给计数命令，重定向把匹配行本身写入文件。

</details>

有余力的话，可以用 `session.log` 做一次分组计数。类似 SQL 的 `GROUP BY`，先取得分组字段，再把相同值聚到一起，按组计数。

```bash
cut -d ' ' -f 1 'practice/day2/session.log' | sort | uniq -c
```

`cut` 按空格取第 1 个字段。`sort` 把相同的级别排在一起。`uniq -c` 对相邻的相同值计数。应得到 ERROR 2 条、INFO 2 条、WARN 1 条。

**过关标准**

能画出数据经过管道的去向，能正确选择 `>`、`>>` 或 `2>`，还能说出哪个文件会被覆盖。
