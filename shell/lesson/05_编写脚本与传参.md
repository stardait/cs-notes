# 第 5 课｜编写脚本与传参

**用时约 50 分钟。** 把查看日志开头的命令变成一个可重复使用的脚本。每一步只改一件事，跑通了再往下。以下操作从 `shell/` 开始。需要日志样本时，先回到 [第 3 课](03_查找文件与搜索内容.md)。

用 `mkdir -p 'practice/review'` 准备复盘目录。下面逐步编辑 `practice/review/show_log.sh`，保留你已完成的 `scripts/show_log.sh` 作为对照。

## 1. 第一个脚本可以只有你已经会的那条命令

现在要反复查看一份日志的前三行。把熟悉的命令保存到文件，省去每次手敲。用编辑器新建 `practice/review/show_log.sh`，保存为 UTF-8、LF。文件里先只有这一行。

```bash
head -n 3 'practice/day2/session.log'
```

回到终端，明确让 Bash 读这个文件。

```bash
bash 'practice/review/show_log.sh'
```

现在应该打印样本的前三行。脚本里发生的事和你直接敲 `head` 一样。差别在于，这次启动的 Bash 从文件读取命令。若要换日志，目前需要编辑这个文件。接下来解决的就是这一点。

## 2. 先看参数有没有送进来，再让 `head` 接它

像 Python 函数通过参数拿到输入一样，脚本也能从调用命令拿输入。先把练习脚本内容换成这一行，只观察 Bash 收到了什么。

```bash
printf '第一个参数=<%s>，参数个数=%s\n' "$1" "$#"
```

回到终端，在脚本路径后多加一个值，再试一次带空格的两个版本。

```bash
bash 'practice/review/show_log.sh' 'practice/day2/session.log'
bash 'practice/review/show_log.sh' 'practice/day2/session copy.log'
bash 'practice/review/show_log.sh' practice/day2/session copy.log
```

`$1` 取脚本收到的第一个参数，`$#` 取参数个数。`bash` 已经用掉了脚本文件这个路径，所以它在脚本里另有名字 `$0`。前两条各有一个参数，最后一条会得到两个，而 `$1` 只有 `practice/day2/session`。这一步只打印参数，带空格的文件暂时没有创建也能观察。

## 3. 用变量给路径起名字

我们想把 `$1` 当日志路径使用。给它起一个能读懂的名字 `log`。赋值语法是 `名字=值`，等号两边紧挨。否则 Bash 会用空格来分隔单词，无法把整句识别成这次赋值。读取变量时再写 `$log`。

继续把练习脚本改成这三行。

```bash
log=$1
printf '日志路径：%s\n' "$log"
head -n 3 < "$log"
```

第 4 课用过 `<`，这里仍是 Bash 打开一个文件，把内容送到 `head` 的标准输入，只是文件路径这次来自变量。`"$log"` 让变量展开后的文字仍是一个完整路径。`'$log'` 则会原样保留美元符号和字母。

先用 `cp -i -- 'practice/day2/session.log' 'practice/day2/session copy.log'` 创建带空格的样本。已有课程副本时可以保留。再运行下面两条，看同一个脚本怎样读取不同路径。

```bash
bash 'practice/review/show_log.sh' 'practice/day2/session.log'
bash 'practice/review/show_log.sh' 'practice/day2/session copy.log'
```

每次先出现你传的路径，再出现同样的前三行。调用处的引号让 Bash 把文件名交给脚本时算作一个参数。脚本里的双引号让路径在展开后仍保持完整。

## 4. 参数不对时，为什么要先结束脚本？

试着只运行 `bash 'practice/review/show_log.sh'`。这时 `$#` 是 `0`，`log` 没拿到路径，读取文件时就会报错。我们可以在读取之前自己检查，并告诉调用者应该怎么用。

先用人话写出分支。「如果参数个数不等于 1，就打印用法并结束。检查通过，再取路径读文件。」这段条件放在 `log=$1` 前面。

```bash
if [[ $# -ne 1 ]]
then
    printf '用法：bash %s 日志路径\n' "$0" >&2
    exit 2
fi
```

- `[[ ... ]]` 是 Bash 的条件检查。这里把 `$#` 和 `1` 作为两个数字，`-ne` 问「是否不相等」。方括号两侧要留出分隔用的空格，`-ne` 也单独占一个词。
- `if` 检查紧跟着的条件，成立才运行 `then` 后面的命令。`fi` 结束这一段。和 Python 的 `if ...:` 相比，Bash 用这两个词标出分支边界，缩进帮助人阅读。
- `>&2` 是 `1>&2` 的简写，把这次打印的正常输出接到标准错误。它沿用第 4 课的通道编号。这里想让用法说明走诊断通道，`>&2` 后接的是通道编号。
- `exit 2` 结束执行这个脚本的 Bash，并把数字 `2` 交回调用方。我们的脚本用它表示用法有误。把这段写在脚本文件里，直接在交互窗口执行 `exit` 会结束当前 Bash。

## 5. 拼起来再验证

<details>
<summary>完整脚本，用来对照你的版本</summary>

可在第一行写 `#!/usr/bin/env bash`，声明直接执行这个文件时使用 Bash。我们本课用 `bash 文件名` 调用，解释器已经在命令行指定。

```bash
#!/usr/bin/env bash

if [[ $# -ne 1 ]]
then
    printf '用法：bash %s 日志路径\n' "$0" >&2
    exit 2
fi

log=$1
printf '日志路径：%s\n' "$log"
head -n 3 < "$log"
```

</details>

```bash
bash -n 'practice/review/show_log.sh'
bash 'practice/review/show_log.sh' 'practice/day2/session copy.log'
bash 'practice/review/show_log.sh'
```

`bash -n` 检查语法，成功时通常无输出。再实际运行一次，检验能否读带空格的文件。最后少传一个参数，应该只看到用法说明。若报错里出现 `$'\r'`，检查脚本的换行格式是否已设成 LF。

## 6. 独立练习

1. 把脚本改成只显示前 2 行，先用 `bash -n` 检查，再用含空格的路径运行。
2. 空着路径参数运行一次，确认脚本会给出用法。再恢复正常参数，确认脚本能继续读文件。
3. 解释如果把打印路径那行的 `"$log"` 改成 `'$log'`，屏幕上会出现什么。

<details>
<summary>参考答案与检查</summary>

把最后一行改为 `head -n 2 < "$log"`。正常输出的两条日志应是 `INFO start` 和 `ERROR cannot open file`。只运行 `bash 'practice/review/show_log.sh'` 时，`$#` 为 `0`，因此会给出用法。`'$log'` 会传入字面文字 `$log`，双引号中的 `"$log"` 才会展开变量。

</details>

**过关标准**

能从一条写死路径的命令开始，自己推到带参数的脚本。给你一个含空格的路径，能解释它在哪两次需要保护参数边界。学完旧版的话，可以回头读自己的 `scripts/show_log.sh`，给每一块写一句「它解决了什么问题」。
